# 宿主边界重新划定与越界代码整改计划

日期：2026-10-12。

状态：代码整改与回归已完成；真实 PPT 页面复验因当前 UI 自动化不支持文件选择而待完成。

依据：用户明确要求宿主负责原始消息传递、上下文引用解析和按历史索引升序装配，禁止宿主擅自判断、筛选、解释或决定角色后续行为。代码基线为 `3fbda85`；[排查记录](../../.codex-workspace-mcp/host-message-audit-20261012.md)包含 21 段原代码及调用位置，部分段落属于同一问题的调用链，不代表 21 个独立方法。

本计划覆盖排查中发现的消息处理和执行策略问题。此前历史树计划将停滞检测列为另议；本计划将其中的宿主语义判断与强制交接纳入整改，技术资源上限另按明确配置保留。

## 一、目标边界

宿主是消息与调用的执行载体，不是新的发言者、任务分析者或决策角色。

用户、Organizer、Worker、Observer 和工具产生原始消息。AI 决定当前要做什么、需要哪些历史、哪项要求有效、结果意味着什么、是否继续或结束。宿主按照明确的请求和既定协议保存、查询、传递、装配与执行，不补写另一套意见。

| 工作 | 宿主允许做的事 | 宿主禁止做的事 |
| --- | --- | --- |
| 消息存储 | 保存原文、原执行者、现有引用和时间 | 改写原话、以宿主摘要替代正文、伪造角色返回 |
| 查询历史 | 执行 AI 指定的查询、范围、分页或引用 | 自行认定哪些成功、失败、说明、图片不值得读取 |
| 上下文装配 | 解析明确引用，按原始顺序恢复消息 | 在 AI 选择之前按业务含义或消息种类预选 |
| 消息路由 | 执行明确的接收者与访问范围 | 将“不能直接通信”扩展为“这类事实没有阅读价值” |
| 来源与协议 | 维护调用关联、原图引用及协议字段 | 在原正文前加说明、插入来源文字块、冒充用户指令 |
| 工具执行 | 执行 AI 已发出的合法调用，传回实际结果 | 猜测不必执行，改用另一次调用的旧结果 |
| 技术检查 | 检查引用、协议、结构化权限、配置容量和资源预算 | 判断任务重要性、完成情况、有效要求、调查是否足够 |
| 日志 | 保存每次实际请求、响应与执行状态 | 将宿主诊断标为 Worker、Organizer 或 Observer 的原话 |

权限、协议和预算检查必须有明确输入与可检查条件，不能用“机械检查”的名称隐藏任务语义判断。

## 二、必须禁止的行为

1. 按消息种类、角色身份、成功或失败、关键词、轮数、是否改文件，判断内容是否重要或任务是否有进展。
2. 自行决定哪条用户要求有效、哪次返回已足够、是否重新调查、是否复用成果、是否拆分或补齐。
3. 向模型临时添加“应该怎样做”的宿主消息，包括 `system` 提示、`guidance`、`correction_instruction`、`view_note` 和自然语言阶段说明中的行动建议。
4. 包装角色原正文：添加 `Source: ...` 前缀、标题、解释、摘要，或者向原图片消息插入宿主说明块。
5. 将宿主构造的任务说明、状态摘要当作新的用户消息，或者将宿主观察到的异常登记为角色真实交接。
6. 因查询参数相同、结果文字相同、缓存仍新鲜而吞掉新返回、合并不同执行，或者替换 AI 的工具调用。
7. 依据固定停滞或重复计数，替 AI 选择交接、禁止继续同目标、要求改变做法或结束任务。
8. 把上述判断迁移到工具内部、目录模块、上下文模块、配置字符串或另一个辅助函数，保留同样的隐式接管。

计数、时间和覆盖范围可以记录，但是否意味着重复执行、信息无用、任务停滞或目标完成，由 AI 根据原始证据判断。

## 三、原文、来源、索引和时间

继续使用当前 Agent 工作区的 `.codex-workspace-mcp/codex_state.db`，不新增另一份业务历史：

- `agent_tasks` 保存会话信息，已有 `created_at`、`updated_at`。
- `agent_task_events` 保存消息与事件，使用已有 `(task_id, seq)` 定位原记录，`timestamp` 是写入时的 Unix 毫秒时间。
- `agent_request_contexts` 保存实际发送的模型请求视图，不能把视图中的引用再次视为新的工具执行。

宿主根据 AI 的查询或选择取得条目的原始编号。同一会话按 `seq` 升序装配；同一原文的切片按原切片位置排列。时间用于查询与展示，不替代会话内的顺序编号。不新建一套模型可见编号，也不需要为了装配重新给原消息编号。

例如 AI 选择同一会话中的 `[12, 3, 8]`，宿主恢复为 `[3, 8, 12]`。今天通过查询读取到的旧消息仍使用旧消息的编号，不能使用今天查询回执的编号重新定位其历史位置。不同会话的局部 `seq` 分别处理，不能直接混排为一条历史。

正文与来源独立保存。原始文本保持空白、换行及内容；图片保留原始引用和像素读取路径。API 必需的 `role`、`name`、`tool_call_id` 和多模态协议可以机械适配，但不能借适配增添正文。

完整来源用于引用解析、查询与日志；模型需要来源时，通过明确的读取协议取得独立的来源字段。不得把供应商不支持自定义字段作为向原正文拼接 `Source:` 的理由，也不得声称未被供应商传递的字段已经被模型看到。适配器的来源交付方式需要单独验证。

原生 assistant/tool 消息保持完整关联。排序不是拆散协议、重新执行旧调用的理由。同一条历史的多次读取可以指向相同来源；不同调用即使同文同参，也保留各自身份和原返回，不由宿主合并为一次业务操作。

## 四、目标请求链路

1. 接收用户或角色原始请求，以及明确的调用、路由、权限和容量配置。
2. 保存原消息；执行已明确发出的合法工具或历史读取调用。
3. 接收 AI 给出的查询条件、范围和选择引用；从 SQLite 解析对应原文与原始 `seq`。
4. 保留 AI 已选择的消息和授权视野内后续新消息，按原顺序装配，维护工具协议与图像引用。
5. 检查最终输入容量；实际发送前保存完整请求。
6. 将实际响应或调用层错误状态原样返回，不增添业务解释或行动建议。

窗口未超限时，宿主不能提前排除新消息中的成功结果、失败、说明或能力限制。跨任务范围必须来自明确的查询或 AI 选择，不能由 `organizer_view()` 将“本次 request_id”默认升级为历史相关性规则。

接近 256k 上限时，继续由接收角色 AI 选择必要原文，宿主只提供容量数值、已有引用、覆盖范围和读取入口。选择阶段依据明确配置运行，不临时生成任务建议；不先由宿主筛掉一部分正文，也不先展开全部历史再要求 AI 重查。最近消息的可用范围只由顺序和容量决定。必要原文无法装入时返回具体容量结果，不替 AI 改选。

技术状态和选择协议采用明确的数据字段；角色如何理解部分历史、读取缺口或核查完成情况属于角色职责。不会因为删除宿主临时提醒，就把所有旧提醒直接搬进角色提示词。需要保留的通用角色规则应独立审阅，不能含宿主对当前任务的推断。

## 六、错误、权限、资源与重试

宿主不新增任务意见，不等于丢弃真实运行异常。模型供应商、数据库、工具及适配器的错误作为调用结果或诊断状态记录，保留原错误、请求身份和发生时间；不能标为角色原话，不能据此自动写出业务结论。

工具不存在、引用越界、权限不允许、协议关联缺失、输入超容量时，返回具体检查结果。不得附加“你应该重新调查/缩小问题/结束任务”等宿主建议。实际任务如何恢复由 AI 决定。

用户配置的权限、取消、超时、模型输出额度和运行预算继续生效。达到限制时机械停止或返回状态，不自动宣称目标未完成或已经完成，不为最后总结额外发起模型请求，不假造角色交接。预算变更必须来自明确配置，不能以删除语义停滞规则为由取消资源控制。

相同调用身份的传输重试与消息重放必须区分实际执行和回执交付；不能重复产生业务副作用。不同调用身份不能仅因参数或文本相同就被宿主合并。工具内部缓存若保留，必须属于明确的调用协议并如实返回采样与执行身份，不能迁入原有的隐式任务判断；正常新调用不得被宿主自行改成读取历史。

## 七、角色与目录边界

本计划不改变角色的历史权限和通信关系。按已明确的角色安排，Worker 是 Organizer 的执行调用，接收 Organizer 原命令、明确输入和本次调用过程；Observer 意见发给 Organizer。宿主执行这个明确路由，不再推断额外的相关性规则。

[历史树目录计划](history_tree_and_message_delivery_plan_2026-10-12.md)提出的 Worker 与其他角色同等历史读取权限，属于单独的角色权限变更，本计划不据此自动开放。历史目录可以随后实现，但不是修正宿主边界的前置条件。

目录由 AI 提交标题、关联和原文引用；宿主只校验、存储和解析。目录不能变成宿主的新摘要、重要性排序器、完成判断或上传次数账本。

## 八、实施顺序

1. **建立请求对照与边界断言。** 保存代表性历史和最终模型请求，按本清单标注每段正文的真实来源、宿主新增内容及 AI 选择调用。明确现有行为与目标行为，不把旧错误断言当成新验收条件。
2. **统一原文与来源装配。** 处理 `with_source()` 全部调用方、原图与重放；建立原文不变、引用解析、同会话升序和原生工具关联检查。日志保留完整实际请求。
3. **移除内容预选与宿主临时发言。** 整改 Organizer、Observer、context_rebuild 和角色提示装配路径；验证窗口未超限及超窗两种路径，不用扩大超时替代修正。
4. **移除执行决策接管。** 整改工具结果指导、观测替换、重复回执吞掉、停滞限制、关键词语义识别和虚构角色交接；补齐结构化错误与明确资源控制的真实返回。
5. **更新角色配置、回归与文档。** 审阅需要的通用角色职责，保证没有把宿主规则整体迁入提示词。更新 README 和相关计划，保留原排查记录作为代码基线证据。
6. **真实任务与原会话复验。** 正常 PPT 任务及续聊各验证一次，检查实际请求、原始执行身份、错误恢复和结束行为；不只检查最终汇总文字。

历史树计划的两处预筛选整改与本计划重叠，以这里的宿主边界为约束，不维护两套相反的实现。既有历史和旧请求快照保持原样，不回写清洗成“从未存在宿主提示”的记录。

## 九、验证场景

| 场景 | 必须验证的结果 |
| --- | --- |
| 未超窗的成功、失败、中间说明、能力限制及图片投递 | 授权视野内的新原消息不因种类或结果被排除；正文能对应原记录。 |
| AI 选择 `[12, 3, 8]`，再读取较早原文 | 最终按原 `seq` 升序装配；新查询回执不改变旧原文的位置。 |
| 跨会话、长文切片与多模态 | 会话局部序号不混排，切片位置明确，原图及原生调用关系保持。 |
| 超窗选择与单条过大原文 | 保留业务正文可追溯到 AI 明确选择；无宿主预选、摘要替代、正文截短或自动重新选择。 |
| 同参数的新查询返回不同结果 | 两次实际返回都可定位；后一次不会因查询指纹重复而消失。 |
| 一次操作、多次读取同一回执；不同调用返回同文 | 原调用身份保留，引用不生成新执行；不同调用不合并。宿主不据引用次数生成业务结论。 |
| AI 明确调用 HTTP 或进程读取，另有旧缓存 | 执行新调用或按其明确参数读取指定旧结果，不由宿主猜测复用；记录实际执行身份。 |
| 多轮读取、无文件变化、重复目标继续 | 宿主不作语义停滞判断、不拒绝合法 AI 决定、不生成缩小/拆分建议；明确资源预算仍按配置生效。 |
| 用户引述禁令与实际行动限制 | 不由关键词误改工具权限；AI 遵守真实用户要求，宿主结构化权限不能被 AI 提升。 |
| 请求超时、空响应、图片请求失败 | 原始错误和交付状态完整保存；没有伪造角色交接、自动视觉结论或宿主下一步指令。 |
| 引用错误、权限拒绝、预算耗尽 | 具体检查结果可见，不静默遗漏、不生成任务完成结论或强制总结请求。 |
| 服务重启与原会话续聊 | 原文、来源、选择引用及日志恢复；不会重新包装旧原文、隐式重做操作或自动填满上下文。 |
