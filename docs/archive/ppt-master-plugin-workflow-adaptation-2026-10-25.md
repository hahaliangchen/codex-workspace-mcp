Strategist、Image_Generator、Executor 是职责角色。切换角色不等于创建子 Agent，也不等于为每个阶段创建临时任务。并行执行仍遵从用户与已确认宿主规则，不能因复制了上游角色名称就自动启动多 Agent。

## 4. 必须明确登记的产品差异

### 页面表达与保存

上游生成路线以 SVG 页面作为完整设计源。当前产品以 PPTX 为持久化稿件，HTML 是当前页面的临时编辑视图。需要保留这个已经确认的产品设计：get_design → HTML/CSS → apply_html → 保存 PPTX。不能同时要求模型维护一套 svg_output、另一套 HTML 和一份原生稿。

HTML 布局由 AI 自由选择，浏览器测量后转换。保留固定品牌资产、稳定对象身份和明确的用户约束。不要强制 Grid/Flex、禁止绝对定位，或用复制上游 SVG 字号/形状校验规则限制本地 HTML 的表达。实际不能转换的内容由工具如实说明；不把技能描述当成转换能力已经存在的证明。

### 模板的含义

上游 Brand/Style/Layout/Deck workspace 与本产品的原生 PPT 模板不是同一种数据结构。上游明确把“原始 PPTX 模板加新内容、保留设计”归到 Edit Native。

适配时必须说明：用户要保留模板原有页面结构，还是只使用品牌素材并重新设计内容。已明确的意图直接采用，确实有歧义才问。模板 ID/版本通过 list_templates 和现有模板服务解析，不能从模板名称猜上游 workspace 路径；产品中已有的选择也不能重新变成候选菜单。

现有“标注/发布 PPT 模板”仅覆盖当前产品能力，不应冒充上游完整的四类 workspace 创建流程。

### 确认方式

上游 Default 有两阶段确认；当前产品主要使用版本化大纲卡片。不能在 skill 中写“完整照搬上游”，实际却只展示页标题。

建议第一轮继续使用现有卡片机制，但让用户可见并确认本轮有效的沟通目标、模板/品牌约束、完整逐页方案和实际支持的制作选项；已由用户明确给出的内容不重复追问。合并为一次确认属于显式的本地交互差异。若要逐项恢复上游两阶段交互，需要单独补对应 UI 和回执，不能由提示词宣称已经具备。

复用 commit_design_spec 保存提案和现有真实确认回执。未确认的项目设计文本只是草稿；执行以用户实际确认的计划版本为准。上游 spec_lock 的稳定锚点应映射到同一确认版本的约束，不要求 AI 再手抄第二份相互独立的主计划或锁文件。

### 检查与素材能力

默认不调用模型视觉检查，溢出/遮挡诊断保持提示性质；不能借恢复上游流程重新加入强制视觉验收。上游也把 visual-review 放在用户明确请求的条件分支。

素材准备只启用真实可用的工具：现有附件/项目图片，以及 create_svg_asset 等已声明能力。图像生成、网页取图、音频、动画等上游能力，须有真实工具及存储链路才能作为可执行分支。不能通过复制参考文档让模型误以为它们已接入。

## 5. 建议恢复后的制作主线

1. 使用用户现有需求和来源材料，确定任务属于哪种已支持的制作意图。只有关键事实缺失才补充询问或研究。
2. 确认所选模板及版本、可用素材；已有选择直接采用，目录只用于发现和解析。
3. 复用已有项目，或调用初始化并等待实际就绪结果。accepted 不等于就绪；初始化未完成时只做尚未完成的独立准备，不轮询、不重复读取已经备妥的同一材料。外部失败按恢复契约报告或续做原项目。
4. 按上游策划职责形成完整方案：沟通目标、依据、逐页核心信息、内容关系、素材、整稿节奏及视觉方向。调用 commit_design_spec 后等待用户确认生效版本。
5. 执行前准备方案实际需要且工具支持的素材。未准备好的必需素材不能在页面里伪装为已完成；可选能力未启用则不运行。
6. 逐页制作：取得当前页有效基线、按确认内容设计 HTML、提交并取得应用/保存结果，推进到下一页。已保留的有效材料直接使用；版本过期、用户改稿或当前材料确实缺失时再读对应内容。
7. 对照完整页纲核对内容和实际保存状态。诊断是提示；转换失败、保存失败和必需内容缺失必须如实处理。模型视觉检查只在明确请求时执行。
8. 当前需要的修订保存后导出，报告对应文件、保存版本及未解决的问题。恢复任务时从有效方案和当前稿件接着做，不从模板目录、规范文件或任务树重新走一遍。

这条主线只描述 PPT 制作，不规定 create_task、finish、步骤迭代或上下文淘汰算法。

## 6. 文件组织与改动边界

先在独立目录准备适配版和逐文件差异，不覆盖原版，也不把上游 13,030 个文件全部塞入当前插件的可读取执行包。

建议职责：

- SKILL.md：仅保留用途、支持的入口、如何选取流程和不可越过的确认边界。
- workflows/：每条已支持路线只有一个流程权威；恢复规则只有一个归属文件。
- references/：上游策划、内容与表达、素材归属的相关指导；按当前路线和阶段读取。
- adapters/：当前插件工具映射、HTML 编辑契约、确认卡片与产物对应关系。工具行为和格式限制集中在这里，避免在所有角色文档里重复。
- 来源记录：逐文件标明上游路径、提交号、保留部分、本地差异和原因；保留原作者及许可证信息。

旧 SVG 执行流程、历史视觉必检规则、无效资源链接、针对某轮测试写入的临时告诫，从活动执行入口退出。上游保留在独立原始仓库，旧本地版本保留快照用于对照；不在同一活动包中留下两套可竞争的制作流程。

PPT 后端负责项目、模板、素材、计划提案和保存/导出事实；前端承接真实确认与稿件编辑；引擎负责转换；通用 Agent 只提供任务执行和上下文能力。没有对应产品能力的上游分支单独列为待实现，不偷偷改变通用 Agent 去模拟。

## 7. 与通用 Agent 上下文问题的边界

上游流程假设有效方案、执行锚点及当前所需材料在有效执行上下文中可用；它没有规定“每轮只留一个工具结果”。目前材料 A/B 的完整正文交替被移出，是独立的通用上下文问题。

不能把这次适配变成固定保留最近两份资料、所有资料永久常驻，或在 skill 中反复要求 read_asset。需要区分当前仍在使用的材料与已完成操作的历史原文，并由通用 Agent 的资产驻留/恢复机制落实。模板目录不是持续的设计依据；确认后的模板选择和实际模板说明各有不同用途。这一问题必须另列缺陷，不能把 skill 换完就声称已经解决。

## 8. 实施顺序与核对标准

1. 冻结当前插件快照，列明现有真实能力及本地交互差异。
2. 以 6.7.3 原文逐文件准备适配版，先完成生成/基于模板制作这一条主线，再处理其他产品入口。
3. 逐条核对：此处是否保留了上游原本的输入、决定者、产物、确认与后续动作；若改变，是否标明了本地原因。
4. 静态校验资源链接、工具名称及输入字段、路线引用、无条件加载的材料；保证没有不可执行的 shell/SVG 路径、未接入功能或重复的流程权威。
5. 用本地模拟工具验证已有需求不重问、提案待确认不生成、同一确认版本续做、未就绪不提前提交、失败结果不串任务、保存冲突与过期版本按实际结果处理、停止/恢复不从头读材料。
6. 验证通过后再替换活动包、重建工具定义并部署。真实模型生成测试需按用户当时授权另行执行，发现问题即停止并复盘。

本报告不授权自动启动真实生成，也不把改造方案当作已完成实现。
