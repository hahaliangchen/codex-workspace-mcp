# 任务 / 步骤迭代器设计

更新日期：2026-10-24。本文采用本次确认的新约定，取代此前由 AI 创建步骤、首次无工具调用即结束的设计；旧图迭代文档与本文冲突时以本文为准。

## 1. 职责

- 任务节点由 AI 调用 `create_task` 创建，承载目标和独立上下文。
- 步骤节点由宿主在每次执行 AI 调用前创建，记录一次 AI 调用及其响应，以及该响应触发的工具调用和结果。同一轮多个工具属于同一个步骤，无工具的响应也属于一个步骤。
- finish 节点由宿主随任务创建。finish 只接收总结、结束当前任务和交还结果，不调用 AI，不验收完成质量。
- 通用 Agent 不强制列计划。代码 skill 对需要规划的工作，把独立计划项拆成子任务；计划项不是执行步骤。

## 2. 执行循环

```text
用户请求 → AI 说明做法并调用 create_task
                  ↓
             建立任务和 finish
                  ↓
             宿主建立步骤 → 调用 AI
                  ├─ 有工具 → 执行并记录结果 → 下一轮步骤
                  └─ 无工具 → 在当前任务上下文追加收尾确认
                                      ↓
                              建立步骤 → 调用 AI
                              ├─ 有工具 → 恢复普通执行
                              └─ 无工具 → 回复作为总结传给 finish
                                                 ↓
                                    结束当前任务并交还总结
```

收尾提示：

> 当前任务是否已经结束？如果已经结束，请总结执行结果；如果尚未结束，请继续调用工具完成工作。当前任务仍在执行；仅在需要处理独立子目标时创建子任务。

宿主只根据有没有工具调用推进，不解析回复里“结束了”等文字。收尾期间当前任务仍然存在；有新用户输入或异步结果时恢复普通执行，之后重新确认。没有创建任务的纯问答可以直接返回，不额外确认。

结束只表示本次执行交还。用户检查实际结果，发现遗漏后描述新的目标，再创建任务处理。停止、请求上限和异常仍保留宿主原有的运行控制，不代表进入 finish。

## 3. 执行归属

一段对话可以同时有多个执行上下文。每个上下文分别维护：

- Agent 身份：`Session.agent_id`，串行任务切换不能改变它。
- 当前任务：`Window.task_node_id`。
- 当前步骤：`Window.current_step_node_id`。
- 执行阶段：`Window.confirming_finish`。
- 返回位置：子任务 finish 的 iterator，包含调用方任务、scope、工具调用 ID 和请求引用。

Session 在每轮从 Window 取得任务和步骤身份，事件显式携带归属。`task_id` 是现有对话存储键，`node_id` 才是任务树节点 ID，不混用。

主 Agent 的 `active` 查询只用于主执行链恢复及兼容旧记录，不用于推断其他 Agent 的当前执行位置。并行节点的状态互不清空。异步子 Agent 总结、视觉结果和插件结果交给发起它们的任务。

## 4. 串行子任务

执行中遇到需要先处理的独立目标时，先说明问题和准备如何处理，再调用 `create_task`，传入 goal、reason 和必要 briefing。

- 子任务挂在发起调用的执行步骤下。
- 保存父上下文和尚未返回的工具调用，挂起父任务。
- 子任务使用新的上下文，携带目标、必要背景、用户原话、已加载技能及固定材料；不携带父任务的完整工作记录。
- 子任务也由宿主逐轮创建步骤，并在收尾确认后进入 finish。
- finish 把总结作为父上下文中原来 `create_task` 调用的工具结果交回，删除子任务的工作窗口，恢复父任务。
- 父步骤收到结果后结束，父任务下一次 AI 调用产生新步骤。原始请求、事件和资产继续保留供历史查询。

例如：烧水热菜时，准备打开开关却发现锅坏了。说明检查和维修做法，创建“修锅”子任务并传入故障现象。收到“锅已修好”的总结后，继续打开开关、烧水热菜。

普通读写是当前目标内的工具操作。通用 Agent 不要求每个目标都有多个计划条目。串行子任务仍沿用最多嵌套三层的限制。

## 5. 并行子 Agent

仅在用户或适用 skill / 插件要求多 Agent 时使用 `spawn_agent`，它创建一个独立子任务并由宿主启动对应 Agent。

- 明确指定数量时，按指定数量创建，受宿主并发容量约束。
- 未指定数量时，由 AI 根据可独立执行的目标决定，最多五个并发子 Agent，主 Agent 另算。
- 每个子 Agent 有自己的任务、步骤、上下文与收尾阶段；可以调用 `create_task` 执行串行子目标。
- 子 Agent 不递归创建并行 Agent。
- 子 Agent 完成收尾确认后，由 finish 结束任务，再由调度器投递总结。一个子 Agent 的结束不会恢复其他 Agent 的执行链。
- 主 Agent 根据依赖等待和整合；收到结果后可以继续工作，最终仍走自己的收尾确认。

`return_task` 不再提供给模型，避免并行子任务有另一套结束规则。原有 Git 分支、合并及结果检查工具保留。

## 6. 步骤记录与上下文

步骤元数据保存请求 ID、scope 和执行阶段；结果保存 AI 响应、工具调用与结果的历史引用，不重复保存大段工具参数或正文。请求上下文快照记录对应步骤 ID。多个工具的原生 assistant / tool 消息保持配对。

后台插件任务和视觉任务在提交时持久化 `owner_node_id`，指向发起调用的步骤；等待和结果投递都从这个步骤定位所属任务及 Agent，不按会话内最新的工具调用 ID 推断。工具调用 ID 只在一轮响应内唯一。旧队列自动增加归属字段，历史归属唯一时可恢复；有多个候选步骤时明确报错，不投递到任意执行链。视觉检查的去重也限定在同一个发起步骤内。

前端按步骤保存的事件引用读取本轮 AI 回复，包括普通执行期间的 draft；工具结果仍归在对应步骤下。结束节点按任务内序号排在步骤后，结束状态显示“任务已结束”，不表示质量验收通过。

任务树保留 React Flow 回传的节点测量尺寸，避免选中状态或历史更新重建节点后丢失尺寸、使节点一直隐藏。桌面与窄屏浏览器用例覆盖实际节点显示、点击详情、本轮回复、工具结果和结束顺序。

每个任务内部共用自己的上下文，步骤不切上下文。新步骤没有 AI 手写的结果摘要，因此不能按旧逻辑把它们直接折叠成空结果；使用已有上下文整理机制处理压力。旧会话里带有显式结果和步骤标记的记录仍可按原方式折叠。

主任务结束后保存一条对话记忆索引。新请求使用干净上下文、最近三十条索引和仍有效的技能材料；相关历史按引用读取。任务中断后可恢复原任务，新用户输入使收尾阶段恢复为普通执行。

## 10. 临时任务自动接收调用记录（2026-10-24）

创建临时任务时，宿主遍历调用方及其祖先任务的步骤节点，按事件顺序装配工具调用记录。每条包含工具说明、简短参数、返回状态、原始结果引用，以及已有资产引用。工具说明优先使用调用参数中的 `label`，否则使用工具定义的 description；旧记录缺失说明时按现有工具定义补齐。

资产引用一次读入内存索引，装配时直接关联，不复制工具结果正文，也不要求 AI 重新总结此前执行过程。子任务的 `briefing` 仍可提供额外背景，但没有它也能收到调用记录；多层临时任务按相同方式收集祖先记录。只遍历所在执行链的任务和直属步骤，不混入其他任务或并行兄弟任务。

工具记录的收集不调用模型，不判断业务重要性，不据此决定重试、创建任务或验收通过。子任务需要完整内容时通过 `read_asset` 恢复已保存结果，无需再次执行原工具。

验证：任务上下文专项 17 项通过，包含新增的双层临时任务自动交接、按引用恢复正文、按时间排序及其他任务隔离用例。全部使用本机模拟模型，未发起真实 PPT 生成。

## 11. 完成检查允许外部阻塞后结束（2026-10-24）

AI 首次没有调用工具时，宿主只陈述这个事实，再询问它是总结结束还是继续推进。任务完成，或外部阻塞导致无法继续时，AI 可以说明结果、阻塞原因和需要用户做什么，然后以第二次无工具回复进入 finish；仍有能推进的工作则继续调用工具。主 Agent 与子 Agent 的系统提示词同步此说明，不再用“当前任务仍在执行”催促继续。

宿主不判断业务是否完成或阻塞，仍按是否调用工具推进原有循环。18 项本地模拟回归通过，新增用例确认外部阻塞总结可以经过 finish 返回并解除活动任务上下文；原有继续执行用例保持通过。未运行真实模型。

## 12. 旧版：当前任务的每轮步骤概要（2026-10-24，已由第 13 节替代）

每次调用执行 Agent 前，宿主复用临时任务交接时的工具活动收集逻辑，从当前任务及其直属步骤的原生事件装配 `task_activity`。概要包含步骤节点、事件序号、工具名称及简短说明、关键参数、原始返回状态、版本/保存/应用等返回字段、工具结果历史引用与已有资产读取引用。主任务、串行子任务和并行 Agent 均只取得当前执行任务自己的记录，祖先任务的交接仍使用 caller_activity。

该概要独立于可压缩的工作对话，每轮只在实际请求中装配一份，不写回聊天消息，也不调用 AI 再总结。资产引用一次读取为内存索引，再关联到相应返回事件。完整正文、HTML、代码和补丁不复制到概要；对应输入只保留大小事实。原始工具结果和已有正文交付保持不变。

为限制输入体积，每轮只列最近 24 条工具调用，保持原事件顺序，并返回总调用数、略去数量及完整任务历史引用。简短说明最多 160 字符，普通长参数以长度表示；选取的返回事实保留原字段名，文本最多 512 字符。旧记录没有说明时使用现有工具定义或工具名。当前任务目标仍由任务路径和主任务锚点提供，不在概要中重复一份。

宿主不判断“已经做完”“应当进入哪一步”“是否该重读”，也不把失败推断成未应用或未保存。读取成功后模型能在靠近当前输入的位置看到已经做过的事情；需要旧正文时可直接按引用读取。

## 13. 按步骤装配工作上下文（2026-10-25）

通用执行 Agent 在每次模型请求前装配工作视图，不再等到容量阈值才收起旧步骤，也不再重复追加一份 task_activity。当前任务较早且已结束的步骤替换为简短操作记录：工具名称、调用 ID、说明、简短参数、原始返回状态、简短错误信息及对应完整结果的资产 ID。最近一步的完整原生调用与所有配对结果保留；用户原话、系统指令、显式任务输入及固定材料保留。异步结果按实际交付时间保留，不因其所属步骤较早而提前移除。

宿主只读取当前工具交换里结构化的 asset_id / asset_ids 引用：若正文已在工作视图中则复用；若只有引用，则直接读取该版本的完整资产，作为下一轮输入。默认不截断正文、不挑业务字段、不用新版本替换明确引用的历史版本、不重放原操作，也不递归追踪恢复数据内部的引用。恢复失败时附上真实错误；显式 release_assets 仍有效。临时恢复数据在下一步骤不再使用时退出工作视图，转成显式任务输入的材料由该任务继续持有。

资产索引按工具及完整参数分组，只列最近一次实际交付的版本。即使内容 A → B → A 复用了 A 的原资产 ID，排序仍依据最后交付时间；旧版本及完整原始事件继续留存。这个分组不判断文件、页面或业务对象是否相同。步骤收起和恢复仅影响模型输入，不更改历史记录或任务完成、权限、并行隔离及验收逻辑。

## 16. 一次建链：串行子任务（2026-10-25）

- `create_task` 一次可以建一条串行子任务链：
  - 没有任务时，`goal` 建主任务，`tasks` 可以同时列出它的第一条链。
  - 在任务里，`tasks` 在当前任务下建链；只给 `goal` 等于只建一个。
  - 调用层的 `asset_ids` 是链上每个子任务共享的参数，条目里的 `asset_ids` 是该子任务额外需要的。`reason` 改为可选。
- 节点一次全部建好，任务树里立即可见。宿主按顺序自动执行：前一个结束就直接进入下一个，调用方一直等待。每个子任务除了自己的参数，还会拿到链上前面各子任务的返回（总结和资产引用）以及自己在链中的位置。最后一个结束后调用方恢复，结果按顺序列出全部返回。
- 链不是一成不变的：子任务执行中遇到意外的工作，就在自己下面建子任务，挂在遇到问题的那一步下面，做完回到原处继续。执行中途不修改剩下的链；跑完后调用方可以再建新链。
- 链中某个子任务没做成时，链照常继续。后面的子任务能看到前面的返回，由它自己判断；宿主不解析"失败"之类的文字。
- 说明文字：工具描述、每轮任务状态、主任务启动说明和两份提示词只说"看得出几段工作时，适合一次建出来"，不写绝对的要求。

验证：

- 真实循环：一次调用建三段链。三个节点同时存在，只有第一个在运行；共享资料是每个子任务的参数。第二段能看到第一段的返回，看不到第一段读过的资料；第二段中途插入一个修复子任务，挂在第二段的步骤下，做完回到第二段。调用方最后按顺序拿到三段的返回，所有子任务窗口都已释放。
- 一次调用同时建主任务和两段链：只有一个调用事件，两段都挂在主任务下并完成。
- 对照：让"进入下一个"失效后，链测试失败。
- 两个旧测试按新契约更新：`create_task` 的 schema 不再把 `goal` 设为必填；插件会话测试里有一次不带 `reason` 的建子任务，现在会成功，改为按工具名查找终端调用的结果（仍被拒绝）。

## 17. 链的启动校验，去掉手动压缩（2026-10-25）

- 建链时校验每个条目声明的 `asset_ids` 是否都存在于本任务。只要有一个不存在，整条链都不创建，作为普通工具错误返回，并指出是第几个条目（`tasks[k].asset_ids`）。
- 链执行中，如果下一个子任务启动不了（资料读取失败，或固定输入连引用都放不下），不再让整轮运行出错。链就此结束：调用方收到已完成子任务的结果，以及 `stopped`（原因、错误、没启动的任务）；没启动的节点标为 `cancelled`。
