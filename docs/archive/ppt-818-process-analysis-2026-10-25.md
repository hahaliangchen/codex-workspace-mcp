## 主要问题

### 1. HTML 文字区域的布局映射丢失

第 2 页成功提交（工具调用事件 402）的局部 HTML 为：

```html
<div data-kind="text" style="display:flex;align-items:flex-start;gap:24px;padding-top:14px">
  <p style="...;width:180px">忙碌 ≠ 有效产出</p>
  <p style="...;flex:1">等待、返工、切换也会拉长工时。……</p>
</div>
```

浏览器中是同一个容器内的左右两段。转换器将该 `data-kind=text` 容器写为一个 PPT 文本框，两段按原生段落上下排列，仍沿用横向 HTML 容器测得的高度。事件 573 的回读结果变成：

```html
<div data-id="new:f71a60ee5dfaaa664325c6b2bfc58cbe:14" data-kind="text"
     style="position:absolute;left:72px;top:368.6px;width:1120px;height:68px;
            display:flex;flex-direction:column;justify-content:flex-start;padding:14px 0px 0px 0px">
  <p ...>忙碌 ≠ 有效产出</p>
  <p ...>等待、返工、切换也会拉长工时。……</p>
</div>
```

第 3、4 页同类区域分别是“因此，不宜只问……”和“建议的起步方式”。三处均在保存后被 `check_layout` 报文本空间不足，成为后续改稿的主要目标。

代码对应：引擎 `src/design/measure-dom.ts` 收集一个文字节点内的多个 HTML 块为 `DesignParagraph[]`，`src/design/export-core.ts` 将这些段落依次写入同一原生文本框。没有保存这些段落在浏览器中的横向相对位置。浏览器文字测量诊断为空，并不说明 HTML 到 PPT 映射完整。

已能确认布局语义丢失；本报告未重新渲染最终成品，不对最终像素效果作新的验收。修复应处理转换映射，而非再强迫 AI 改用某一种布局。
