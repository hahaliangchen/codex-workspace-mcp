# HTML 自由设计与可选视觉检查

按 2026-10-25 的确认：当前 PPT 为唯一持久化稿件，普通 PPT 与 AI PPT 使用相同链路。

## 默认流程

确认大纲 → 读取当前 PPT 的 HTML → AI 自由设计 HTML/CSS → 浏览器计算位置、尺寸与断行 → 写回可编辑 PPT → 保存 → 导出。

用户随后明确要求布局自由：不强制 Grid/Flex，不要求移除绝对定位，由 AI 根据内容与设计意图自行选择构图、样式和布局。当前引擎已有浏览器测量能力，不增加宿主布局判断、布局恢复或独立布局源码存储。用户手动移动后，下次读取当前 PPT 的新坐标，AI 可以据此设计。

本地溢出、越界、遮挡诊断仍是提示，不强制拦截保存或导出。默认不执行模型视觉检查、不要求通过记录或逐页验收。只有用户明确要求看图检查时才调用渲染与视觉模型，现有检查工具继续可用。

## 实施范围

- PPT 插件主 skill、生产流程、HTML 格式规范及旧执行参考中的默认视觉检查要求已移除。
- 引擎 page-tools 的 get_design/apply_html/guide、页面设计说明和 check_layout 说明同步；重新生成后端 page_tools.json。
- 前端大纲确认续写消息不再要求逐页验收；大纲卡片仅展示内容保存进度。
- 插件 session/status 不再读取整份 PPT、计算各页指纹及汇总视觉验收；显式请求的检查记录仍可通过对应工具取得。
- 手动下载标记为 saved_download，表示导出已保存稿件，不因缺少视觉记录标记为草稿。
- 通用 Agent 循环、任务判断、数据库结构和 WASM 未改动。
