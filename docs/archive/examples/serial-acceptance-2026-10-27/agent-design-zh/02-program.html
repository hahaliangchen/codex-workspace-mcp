通用 Agent 设计　/　02　把任务写成可执行流程　语言版本 12
From intent to execution

把任务写成
可执行流程

让流程代码负责顺序、数据依赖与控制流，让 AI 负责明确交给它的理解、生成和业务判断。宿主按规则推进普通代码与工具调用，不把每个表达式都变成一次模型请求。

普通计算：确定性执行智能工作：显式虚函数业务验收：看真实证据
本页路线核心分工一次执行如何推进三类调用串行示例语言边界失败与验收

先分清：流程与判断不是一回事

版本 12 的流程伪代码借用 JavaScript 基础语法，但不是完整 JavaScript，也没有运行 JavaScript 虚拟机。它把常见流程交给 Rust 宿主执行，把需要智能处理的工作显式交给 AI。

01 / 程序

确定“先做什么、再做什么”

函数调用、条件、循环、数组收集与断言表达可预先写清的控制流。普通运算由宿主求值，不会因为出现 i + 1 就额外请求模型。

02 / AI

处理需要理解的工作

内容设计、材料理解、语义检查等工作通过有职责说明和返回契约的 @virtual 函数调用。AI 根据实际输入完成任务并返回 JSON。

03 / 宿主

推进并留下执行事实

宿主管理函数帧、程序位置、工具分发、挂起与恢复、持久化、权限和取消。工具返回不会自动变成业务成功结论。

同一输入、相同工具与任务返回值会产生相同控制流；这不意味着 AI 判断、外部操作或整个业务都是确定性的。

一次执行如何推进

主任务提交唯一的 main。Runtime 根据程序继续运行普通代码；到达工具或虚函数调用时才产生相应的实际步骤。

01 · INPUT主目标与输入目标、要求、材料按实际参数交接
02 · PROGRAM执行 main宿主确定性推进代码与条件
03 · TASK / TOOL工作发生虚函数完成智能职责；工具执行实际操作
04 · RETURN结果回到调用点函数返回 JSON；程序消费结果继续推进
05 · CHECK按要求检查并交付对照真实产物与业务标准作判断

调用、挂起、恢复

普通 helper 在 Runtime 的局部函数帧中执行；工具调用保存实际回执；虚函数在当前 AI 任务上下文中完成职责。函数返回后，宿主恢复原调用位置。main 返回表示主程序结束，不代表宿主已认证业务验收通过。

三类调用，三种执行方式

helper(args)　普通函数

已有代码由宿主在局部作用域执行。它不会因为是一个函数就自动创建新的 AI 任务或另一个 Agent。

@virtual helper(args)　显式 AI 任务

当前 AI 依据函数职责、实际参数和返回契约完成理解、生成、转换或检查。函数注释不是自动执行的代码。

io.read(...)　固定工具方法

通过当前公布的固定库名与工具契约调用。获得工具原始 JSON 后，仍由流程或 AI 按业务要求检查。

fork / join　获授权的并发

只有获得并发授权且工作适合拆分时才使用。join 收集函数返回，不自动合并隔离工作区，也不替代验收。

示例：设计、保存、读回、检查

最小串行示例以完整 HTML 为产物：AI 负责设计和检查，确定性的程序负责写入、读回及消费检查结果。

function main(request) {
  const draft = compose(request);
  const receipt = io.write({path: request.output, content: draft.content});
  const actual = io.read({path: request.output});
  const review = inspect(request, actual.content);
  assert(review.passed, "验收未通过，不能交付");
  return {path: request.output, receipt, review};
}

/** @virtual */
function compose(request) {
  // 根据目标与要求完成设计，返回 {content:string}。
}

/** @virtual */
function inspect(request, content) {
  // 检查真实读回内容；返回 {passed, issues, evidence}。
}

这里的 assert 只在 AI 已返回布尔检查结论后，由宿主确定性消费它。读回正文使检查针对实际文件，而不是只针对生成函数声称输出的内容。

这段示例的内容检查本身不包含浏览器渲染。没有执行浏览器检查，就不能据此声称视觉验收通过。

基础语言子集：够表达流程，不冒充完整 JS

可以表达

普通函数、局部 JSON 值、if/else、常见循环、break/continue、三元、模板字符串、受支持的表达式，以及静态的 library.method(args) 调用。

明确不开放

异步／Promise、生成器、模块导入、TypeScript 类型、箭头函数、闭包、类、动态库方法等完整 JS 能力。未知方法或不匹配的类型会明确报错，不交由 AI 猜含义。

几个容易误读的规则

条件采用 C 风格真值：false、null 与数值零为假，其他 JSON 值为真；空字符串、数组、对象也为真。算术与比较不做隐式类型转换；字符串参与 + 时按规则拼接原始 JSON 值。具体边界以版本 12 语言手册为准。

检查要有证据；失败不能装作成功

不够：工具成功、函数返回、程序结束

这些事实说明操作或控制流发生过，不证明产物满足业务要求，也不证明所有检查都已通过。

更可靠：检查实际对象并记录结果

按任务要求读取实际产物，让检查职责返回明确结论、问题和证据；失败时停止，或在获准范围内修正并复查。

完整源码会在执行前编译；源码错误应依诊断改写源码，不意味着业务操作已执行。运行时失败则不能假定外部写入从未发生；恢复时应依据已有回执和真实状态，避免盲目重放不确定的副作用。
