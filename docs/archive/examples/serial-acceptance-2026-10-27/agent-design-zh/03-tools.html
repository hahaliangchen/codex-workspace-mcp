03 / 工具与证据
执行边界 · 工具契约 · 验收事实

工具不等于权限，
回执不等于成功。

Agent 通过受约束的固定工具接口读写真实资源；宿主执行权限与分发边界，流程负责核对实际结果，AI 负责需要理解与判断的工作。

固定 library.method权限按作用域过滤读回真实产物再验收

本页导航

各自负责什么固定工具契约从读写到证据材料与资产引用验收与失败边界文档依据

通用 Agent 不是“能调用工具就能做任何事”。它在当前任务可见的工具目录内工作：源码表达调用，宿主按原有权限与插件归属分发，工具返回事实，调用方再决定是否满足业务要求。

01 / 职责分界

让每个环节只承担该做的事

流程语言中的普通计算和工具调用由宿主确定性推进；内容生成、理解和业务判断通过显式的 @virtual 函数交给 AI。业务流程与验收标准来自用户要求、技能或插件，而不是由通用宿主猜测。

1

流程程序

串起读、写、循环、函数调用、分支和断言。确定性表达式由 Rust 执行，不因普通比较而额外触发 AI。

2

工具与后端

执行具体操作并返回原始结果、状态或错误。工具受理只表示已受理；它不替调用方宣布目标完成。

3

执行宿主

提供作用域、工具分发、持久化、权限、取消和容量管理；不内置某个业务的生产步骤或验收规则。

4

显式 AI 判断

虚函数依据真实输入和工具证据完成生成或审查，并按约定返回结果，例如 passed、evidence 与 issues。

02 / 工具接口

调用名固定，权限目录不靠猜

规划时获得当前可用工具的自动生成声明；程序源码以静态的 namespace.method(args) 调用。工具参数来自真实 JSON schema，包含相应约束；返回类型来自工具输出 schema，没有返回 schema 时标为 unknown，不虚构字段。

01 · 声明从当前真实工具目录生成接口
02 · 编译检查固定名字、参数与权限
03 · 分发进入原工具分发和权限检查
04 · 回执保存真实工具返回结果
05 · 消费由流程与 AI 按职责继续处理
// 流程源码：固定工具名；读回结果仍需由流程消费
const actual = io.read({path: request.output});
const review = inspectPage(shared, page, actual.content);
assert(review.passed, "实际产物检查未通过");
边界要点：声明与编译器使用同一份权限过滤后的当前目录。未启用或未授权的工具不会因为模型给它起别名就变得可调用；源码不使用 tools.* 或自定义库别名。

invoke_library 是执行 AI 在原生步骤中调用已发布工具的传输包装；其中仍使用同一个固定方法名与原参数契约。它不是流程源码中的另一套调用 API，也不会扩大权限。

03 / 操作与证据

读写只是动作，验收需要实际证据

文件工具提供读取、搜索、写入与编辑能力。修改已有文件时可用版本哈希或精确原文校验，降低覆盖已变化内容的风险。对产物的检查应针对真实文件或后端状态，而不是只相信生成函数返回的描述。

可追溯的流程
  1. 把共享要求和真实材料作为参数传入。
  2. 执行写入，并保留工具原始回执。
  3. 读回目标路径，获取当前实际内容。
  4. 由检查职责对照要求返回证据与问题。
  5. 只有检查通过，才继续交付。
不能替代验收的信号
  • 工具调用成功或状态为 accepted。
  • 函数已经返回，或程序编译通过。
  • 产物数量符合预期，但内容尚未检查。
  • 只检查文本／结构，却声称完成视觉验收。
事实从哪里来工具回执、真实读回内容、明确的业务系统状态，以及对应的任务要求。
判断由谁作出流程消费明确的布尔结果；AI 依据证据作语义判断。宿主不替它认证判断真实性。
04 / 材料与作用域

复用真实输入，不把引用当正文

函数参数按位置绑定为当前函数的真实值。公共材料应通过实参或明确可见的作用域变量传递；需要时可分页读取稳定资产。资产引用保留保存版本与来源入口，但仅有引用不等于已经阅读了完整材料。

读取保存版本

稳定资产引用用于回看已保存的正文或图像；分页读取可用于较长材料。

刷新当前状态

需要核实本地文件的新版本时，明确执行刷新或实际读回；不要把旧快照说成实时状态。

范围不随数据传递而扩大

子函数和协作分支继承的是受约束的工具与作用域快照。共享材料可以显式传给分支，但变量继承不会增加权限，也不会自动把某个分支的局部工作全文复制给其他作用域。

05 / 异常与验收

失败要如实传播，未知副作用不重放

源码在执行任何效果前整体编译。源码校验失败时，执行器返回诊断，由原执行 AI 在同一任务范围修正完整源码；这不同于运行时错误。已发生的写入或其他外部操作不会因重试函数体而自动安全重放，状态未知时应核实或明确报告。

验收规则不是宿主替业务设定的。每项任务需要哪些内容、结构、视觉或业务条件，应由用户要求与适用技能决定。检查真实 HTML 文本不等于浏览器渲染检查；没有实际浏览器渲染证据，就不能声称完成视觉验收。

若任务允许修复，可将问题证据交给有明确修复职责的 AI 工作，再读回实际产物并复查。复查仍失败时停止交付并报告阻碍；不要把写入成功、断言未执行或返回值存在改写成“已验收”。
