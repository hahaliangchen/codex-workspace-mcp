# 任务作用域内的两级容量兜底

日期：2026-10-25。

## 规则

整份请求超过输入预算的 40% 时，按时间从旧到新缩减，目标低于 25%：

1. 先把已完成的原样步骤替换成每步一条的操作记录。每次替换后重新估算整份请求，把新记录本身也算进去。
2. 原样步骤已经收完仍未达到目标，才把最早的操作记录合并进同一个前缀区间。区间只保留起止步骤、操作次数和历史读取入口，不复制逐步内容或资产清单。

没有第二个数量阈值。最新一步、用户原话、目标、声明的输入和钉住的技能不参与运行时折叠。25% 是尽力目标：达到目标或没有可缩减内容就停，最终仍由硬容量检查决定请求能否发送。新执行轮次不再进入旧的 60% 折叠或模型压缩分支；没有新轮次记录的旧窗口沿用原来的兼容路径。

区间使用任务节点及 `after_seq` / `before_seq` 定位已覆盖步骤的历史，并继续沿用 `read_session_history` 的分页能力。原始事件、任务节点和不可变资产不改写。区间内部的资产投递顺序转入宿主索引表 `agent_context_asset_deliveries`，以保留“同一操作最近一次使用哪个版本”的事实；此表不进入模型上下文，回退时按事件范围一起清理。

## 超大材料

模型仍然只传 `asset_ids`。宿主先为整份子任务请求保留共同指令、目标、briefing 和全部输入引用的位置，再按声明顺序尝试装入正文，复用原有的硬输入容量检查及 4096 tokens 余量。能放下的给完整正文，放不下的给引用、总字符数和明确的分页参数，不因正文太大拒绝整个子任务。

只有声明的正文或引用是固定输入。之后用 `read_asset` 读到的页面是普通工作步骤，能够正常折叠。子任务结束释放工作上下文，只返回精简总结及保存结果的引用。用户原话、钉住规则、briefing 加引用本身就超限时，输入检查仍然明确拒绝，并保留父任务现场。

`MATERIAL_OVER_CAPACITY` 回执补充材料长度、请求容量事实、分页入口及处理说明：模型可以只读需要的页面，也可以自行创建有明确提取目标的子任务，要求它分页处理后只返回需要的结果。宿主不自动创建子任务。显式工具送达和隐式引用恢复共用这份回执及硬容量边界；声明为引用的输入不会被隐式恢复成全文。
