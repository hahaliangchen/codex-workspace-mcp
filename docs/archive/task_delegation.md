# 函数并发、结果交接与历史排序

并发是当前流程语言的函数能力。主 Agent 在唯一 `main` 中组织任务，用户或适用技能授权并发后，使用 `fork(helper, args...)` 启动分支，再用 `join(handles)` 收集返回。完整语法和五页示例见[语言手册](../agent-program.md)。

## 唯一派发线路

```text
编译程序中的 fork
  → 固定函数名、有序实参、宿主编译结果
  → 继承实际可见变量与有效技能，建立分支工作帧
  → 分支执行普通代码或显式 @virtual 工作
  → 归档结果、原始事件和资产，释放分支工作帧
  → join 将按句柄顺序排列的 JSON 返回交回原程序
  → 按句柄 workspace.integration_required 检查并合并隔离分支
  → 在主工作区验收真实产物并交付
```

`spawn_agent`／`join_agents` 只是宿主保存效果回执的私有分发标识，不发布为第二套模型编排 API。派发必须对应 Runtime 的挂起 fork 指令；不能由模型自由提交自然语言任务、伪造编译对象或绕过原程序 join。子 Agent 不再派生 Agent，每会话最多同时运行五个分支。

普通 `helper(args)` 在当前 Agent 的局部作用域中串行执行；这与 fork 创建独立执行 Agent 不同。两种调用都按位置传参，不把多个实参隐式打包，也不从历史工具交换重组共享变量。

## 材料与权限

当前形参通过 `program_task_input.bindings` 提供一次。其他仍可见的调用方变量保存在作用域，索引只列名称、类型和大小；必要时 `host.read_scope` 只读取得某个值。共享长材料可以传稳定资产引用，实际需要时再分页读取。

分支继承有效技能和当前模型配置（有独立 delegate 配置时按其设置），继续受原权限、插件归属和项目绑定约束。没有工具组加载状态，也没有整窗复制／大窗历史投影两条委派路径。局部探索、工具交换和错误细节不会整份复制回调用方或兄弟分支。

Git 可写任务继续使用专属 worktree；文件及命令在该工作区执行。完成后归档分支，主 Agent 必须在读取主目录中的分支产物前，用 `host.inspect_agent_changes` 检查差异，再以返回的 head 调用 `host.merge_agent_result` 整合。脏工作树、合并冲突、过期提交等保护仍然有效。非 Git 的明确本地写入有资源归属检查；通用宿主不内置某个业务的资源名称或版本规则。

## 返回与验收

`join` 收集函数返回，不代表业务验收。流程必须按业务 skill 检查实际文件、版本、内容或视觉证据。检查是否通过是显式检查函数的结论，由普通代码消费。`host.review_agent_result` 可用于需要单独留存验收记录的流程，不再要求每个函数额外经过通用的人工完成状态机。

异步完成回执按真实完成顺序保存，`join(a,b)` 的返回值按 a、b 顺序排列。完整报告和资产索引继续归档，主窗口只收到明确返回与引用，不获得分支的工作上下文。终态归档和窗口回收在同一事务提交；失败、取消和重启中断也保留历史与实际产物。

`host.cancel_agent` 只取消本会话的指定分支；父会话取消向分支传播，已发生的外部写入不会回滚。执行器继续使用实例身份和租约，防止多个宿主误收割彼此任务。未知外部结果不会自动重放或判为通过。

## 日志、界面与调用顺序

| 层 | 顺序与用途 |
| --- | --- |
| 原始事件 | 全局 seq 的实际发生顺序，用于审计、恢复和证据引用 |
| 聊天卡片 | 固定在派发位置，卡内按 agent_seq 更新，避免并发文本混杂 |
| 完成交付 | 按真实完成顺序进入调用方的回执索引 |
| 程序返回 | join 按传入句柄顺序返回，不改变实际完成日志 |

`subagent/start` 锚定卡片，`subagent/event` 保存分支原始事件，`subagent/end` 归档返回；可选 `subagent/review` 记录显式验收。相同工具 call ID 由 Agent 归属隔离，不跨分支串结果。视觉任务和插件后台结果另按自己的所属作用域交付，不能被兄弟或串行子函数收取。

回归覆盖编译函数的并发与汇合、真实参数、局部隔离、恢复不重放、写入归属、Git 检查与合并、并发上限、取消、租约和终态回收。历史自然语言委派及任务数组调度已删除，旧记录只作为审计数据保存。

## 分支句柄的工作区契约

fork 返回 {agent_id,workspace}；workspace 含 mode、path、integration_required，隔离Git分支还含 repository、branch。它来自宿主持久化的分配记录，初次派发、重复提交及重启恢复使用同一信息。具体分配以句柄为准，不能仅靠文件名或是否存在.git猜测；这是控制信息，不包装子函数业务返回。

join 仍只等待并返回数组；待合并状态不会使 join 自动改动主目录。共享目录的 integration_required=false，不应调用Git合并工具；隔离分支为true，先检查并合并，再读回验收。标记表达工作区隔离方式，不是合并进度轮询值。主Agent的工作可以和子Agent并行，但所需分支应在主目录新增写入前派发，保持其已提交基线干净。发生冲突或合并错误则按原错误处理，不能复制文件绕过检查。

文档示例已加入这条显式整合线路；回归在真正的独立Git仓库中执行相同示例并检查分支提交已进入主分支，另用省略整合的反例复现主目录缺文件。不再仅使用非Git目录验证并发示例。
