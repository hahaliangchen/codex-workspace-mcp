# 模板制作与 PPT 生成闭环实施计划

日期：2026-10-22。本文保留实施前的目标和阶段门槛；实施与部署已进行，实际完成项、验收证据和限制请以 [实施与验收记录](ppt-template-closed-loop-delivery-2026-10-22.md) 为准，不应把本计划的目标当作已通过结果。

## 1. 目标与已确定的原则

让模板制作、发布、试生成、正式生成、用户手动编辑和 AI 再编辑使用同一条转换线路。模板是一份可继续设计的初稿，AI 根据内容选择复用、轻度调整或重设计，不能退回固定骨架填槽。

1. AI 的所有页面内容编辑均从 HTML 入手，包括文字、图片、样式和布局；禁止恢复 AI 原生 JSON/OOXML 编辑入口。
2. PPTX/OOXML ⇄ 内存 JSON ⇄ HTML 双向转换。编辑器仍使用原生对象；HTML 是 AI 工作视图。
3. 不持久化第二份设计 JSON 或 HTML。文稿以 PPTX 持久化；现有模板名称、摘要、说明、权限、版本等业务数据继续保留。
4. 用户手动编辑结束后自动刷新 HTML；修改提交时先使旧 HTML 失效。撤销、重做、外部版本更新同样处理。
5. 画布沿用 1280×720。页数服从需求，5 页仅是测试样例，必须覆盖 20 页及中途失败恢复。
6. 现有 Logo、品牌文字、固定背景和品牌装饰默认保留。只有明确设为占位或可变，才允许 AI 修改。禁止 AI 根据主题、审美或自己的推断解除保护。
7. 模板中的内容布局允许复用或调整；明确的参考图应根据新主题重做，不能把旧内容图作为成品直接复制。
8. 复杂对象可以作为独立 PNG 预览，保留原素材或原 OOXML。未修改时继续原样导出，不能整页栅格化或反复降低素材质量。
9. 不新增自动填槽、自动缩字或自动套卡片算法。浏览器 flex/grid 负责计算 AI 所写布局；转换器负责测量、验证和翻译。
10. 本轮先完成一个模板的完整验收，再交付模板转换标准；不批量迁移现有模板库。

## 3. 目标流程

```text
上传 PPTX / 复制已有模板
  → 草稿编辑器 → 内存 JSON → HTML 投影
  → 整理用途与固定素材规则；手动编辑或 AI 修改 HTML
  → 校验与预览 → 在独立副本试生成
  → 发布模板版本（PPTX + 既有说明/缩略图/元数据）
  → 正式项目固定选中的模板版本
  → 选择/复制模板参考页 → AI 设计 HTML
  → 测量、差异合并、保护检查 → JSON → PPTX
  → 编辑器渲染及视觉检查 → 必要时修改 HTML
  → 保存成功 → 用户手动修改 → 自动刷新 HTML
  → AI 从最新 HTML 继续修改
```

试生成和正式生成共享上述生成服务、工具、模型权限和检查流程，区别仅是目标项目、任务上下文和结果展示。试生成不得修改模板草稿或已发布版本。

## 4. 最小模板语义与保存方式

### 4.1 用户看到的配置

保留页面用途、版式名称、适用说明、真实示例、整体风格描述。字段名是语义提示，不是必须机械填充的槽。

对象只需要三种主要用途，不再让制作人必须配置重复项数、填槽结构等细节：

| 用途 | 行为 | 示例 |
|---|---|---|
| 固定 | 不改内容、位置、大小、比例、颜色或图层效果，不删除或遮挡 | Logo、品牌页眉、固定背景 |
| 可变内容 | 可编辑文字、替换图片、调整版面，保留有价值的风格 | 标题、正文、作者日期、图片占位 |
| 参考素材 | 参考视觉或语义，允许按主题重做、替换或删除 | 总结图示例、流程图示例 |

补充可选的一句话说明，如“按本页正文重做因果关系图”。不增加繁琐的对象分类体系。

默认规则：模板原有未标注图片/复杂素材先固定；已明确标注的图片占位、参考图按标注处理。母版背景固定。已有文字占位和正文用途保持可变。普通内容文字可以作为设计内容，但不得把未标注品牌文字自动视为正文；导入审视时把品牌文字、组合标识和重复页眉纳入固定对象检查。位置和重复出现只能帮助识别，不能成为允许修改的依据。

图像内混合 Logo 与示例内容时，首版保持整张图固定并提示拆分，不让 AI 擅自裁掉品牌部分。

### 4.2 程序内部契约

- 页面：稳定身份、可选用途/版式/适用说明。
- 对象：稳定身份、组关系、固定/可变/参考用途、说明、源对象关联。
- 保护规则：宿主持有权威值；HTML 中的 `data-*` 是投影，不是授权凭据。
- 区分“因品牌固定”与“因转换器不支持而锁定”，后者不能被可变标注强行解除。
- 概念上统一为一个有效策略解析函数，供导入、投影、合并、检查及发布共同使用；不要在五处各写一套判断。

用途规则必须在保存 PPTX、关闭页面、重新打开、发布、复制模板和创建文稿后仍有效。不能只保存在本轮 JSON 的 `metadata` 中。

优先扩展并规范现有形状 `@用途|选项` 标注，兼容真实示例，不再要求显示 `{{TOKEN}}`。页面级语义及不能由当前标注承载的保护信息，使用一个有版本号的、宿主管理的轻量 PPTX 扩展记录；只记录语义与源身份，不存几何副本、不存整份设计 JSON。实施时先验证 OOXML 包的读取、复制、导出及常用办公软件重新保存行为，再确定扩展载体。已有描述文件继续记录风格和自然语言说明，不能成为第二份可冲突的对象权限表。

标注语法只是存储细节；前端通过表单编辑，AI 通过 HTML 语义属性表达。单一解析/写入模块负责二者一致，附最小版本迁移。不要为了此功能构建通用 OOXML 元数据框架。

### 4.3 制作与生成的权限区别

- 普通生成：可改内容和设计；不得重写用途、解除固定标记或伪造源关联。
- 模板制作：允许按制作人要求设置用途、说明和页面语义；AI 的标注提案走已有方案确认界面。
- 将固定元素改成可变属于特殊变更，必须是制作人明确选择或确认的具体对象和变更。AI 不能仅在返回 HTML 中删去 `data-locked` 即取得权限。
- 授权范围由宿主绑定草稿身份、对象 ID 和版本；版本变化则旧方案失效。使用现有确认机制，避免新增复杂审批系统。
- 修改页面用途/绑定元数据也必须计入差异、保存和投影刷新；不能被“外观没有变化”的 no-op 判断吞掉。

## 5. 固定素材的完整保护

1. 导入时统一识别母版、布局层、普通页图片、组合图形及品牌文字；生成有效保护规则。
2. 固定对象不可替换资源、改字、改颜色、移动、缩放、裁剪、隐藏、降低透明度或删除。
3. 不能通过改父组、祖先 CSS、层级顺序、遮罩、重建 ID、复制一份替代品等绕过。
4. 校验有效几何和最终呈现状态，不只比较对象自身的 HTML 属性。
5. 固定 Logo 所在区域不得被新前景内容遮挡。全页背景在其下方不构成冲突；沿用原先合法重叠不误报。首版对新增/变化的前景对象做保守交叠检查，并用最终截图补充确认，不承诺通用逐像素遮挡判定。
6. 固定母版的全页 PNG 预览不能被当作“全页禁止放内容”的区域。品牌避让区域应从源对象提取；无法提取时在模板制作环节确认小范围保护区域。
7. 复制页面时复制资产、保护规则及必要母版关联；新页面生成独立身份，不与原页 ID 冲突。
8. 删除整页属于页面操作，不等于允许删除该页内的固定 Logo；允许用户要求的删页，但剩余页面保护不变。

复杂资产的 PNG 是显示表示，源 XML/矢量图仍保留。替换明确可变或参考资产时才创建新素材，不把整页作为一个图片节点。

## 6. 分阶段实施

### 阶段 A：契约和一个验收模板

交付：用途与保护契约、存储往返样例、固定资产验收夹具。

- 核对本计划列出的断点、前端实际工具声明及后端握手。
- 以用户截图对应的联通/联通元景模板副本作为首个目标；核对实际文件而非仅按目录名猜测。
- 保留右上角品牌标识；标题、副标题、作者、日期设为可变。选择或补一页正文和一页参考图样例作为验收副本，不修改原模板库。
- 自动扫描与人工确认固定元素是否位于母版、普通图片或组合中，覆盖这些表示的差异。
- 完成最小语义保存往返；确认只保存 PPTX 后重新打开，规则不丢失。

阶段门槛：保护规则可持久化，转换不会把 Logo 丢掉或误变成可替换对象。此阶段失败则不继续开放模板 AI 标注。

### 阶段 B：转换器与保护规则

主要文件：编辑器 `src/design/{model,import-core,projection,measure-dom,html-diff,export-core,service-core}.ts`、`src/page/design-bridge.ts`。

- 建立统一用途解析，生成 HTML 属性；保留锁定原因和来源。
- 将允许的语义变化纳入 HTML 差异合并，仅模板制作授权范围可以写回；普通生成提交同样修改须拒绝。
- 在复杂素材、组、引用资产和原 XML 保留之间建立一致规则。
- 做固定素材的直接和间接修改检查，以及固定品牌区域的新增遮挡检查。
- 普通组继续保留关系；明确可变/参考的整组需要重做时，允许受控地整体替换并清理旧子节点。不要放开任意重挂父节点来绕过固定成员。
- 扩展页面管理为可复制所选参考页，保留母版/布局、资源、语义和保护；现有 `duplicateSlide` 能力优先复用。
- 明确页面复制参数与返回的页面 ID/版本。复制属于确定性结构操作，不引入第二套 AI 设计语言。
- 保持基线差异合并、版本检测、事务失败回滚；新用途字段必须加入保护与回归。
- HTML 测量、编辑器渲染与导出使用同一套实际字体。等待字体/图片加载完成再测量；缺字体、加载失败和替代字体明确诊断，不能以错误字体测量后写回几何。
- 固定原生字号、文本内边距、段落/行距和垂直对齐的映射，回归中文、混合字体、换行与居中；不得通过增加默认 padding 或二次自动适配“修正”设计。

阶段门槛：单字修改不影响 Logo；重设计不覆盖品牌区；20 次复制无身份冲突；保存重开后保护仍有效。

### 阶段 C：模板制作和发布

主要文件：前端 `src/view/templateAuthoring/`；后端 `service/ppt_runtime/template_{draft,check,private}.go`；编辑器 `src/api/template-authoring.ts`。

- 保留上传、复制到我的、草稿、原生编辑、缩略图、名称/风格/标签/说明、发布权限和版本控制。
- 用“固定 / 可变内容 / 参考素材 + 说明”简化用途面板；需要时保留原有高级标注读取，不再强制用户配置。
- AI 标注提案显示将变化的对象和用途；重点突出把固定改成可变的项。确认后通过 HTML 语义编辑写回。
- 手工设置用途沿用原生 UI 能力，完成后与所有手工编辑一样刷新 HTML。
- 页面用途可选；一页品牌模板也能发布。不再因为缺少封面/目录/正文/结束页阻止发布，不再因未分配角色移除页面。
- 页名/用途用于检索和选择，不再决定页面是否存在；有重复名称时可自动给出展示编号，不强迫用户改形状名才能发布。
- 前后端统一新验证规则。保留包完整性、可读取、画布约束、资产可访问、身份及策略合法性、保护元数据一致性、转换诊断和明显裁切检查。
- 区分错误和建议：示例内容长短、目录项数量、非等距版式等不再作为旧引擎硬性限制。
- 普通重叠不能一律判错；结合文本裁切、品牌遮挡和实际图片审视。
- 发布保存不可变模板版本，说明与缩略图对应同一 PPTX 版本；失败不发布半成品。
- 描述生成使用最新页面顺序、实际结构及用途；描述不能擅自改变结构化保护规则。

阶段门槛：单页空模板、有布局模板、组合参考图模板可发布；缺角色不删页；无效策略/损坏资产不能发布。

### 阶段 D：正式生成与试生成共用流程

主要文件：前端模板 `tryGenerate`、`DeckEditor`、`PptWorkflowStore`；后端项目初始化、模板选择、任务状态和页面工具声明。

- 模板选择固定 template ID、version/source hash，读取对应说明和 PPTX。既有项目不因模板更新被覆盖。
- 生成前让 AI 读模板实际 HTML、资产、可选用途、固定规则和设计说明。
- AI 根据需求规划页数和选用的参考页；不要求每个输出页机械匹配一种角色，也不默认 5 页。
- 优先复制适合的模板参考页，在其 HTML 上复用/调整；缺少合适版式时，从带品牌背景的基础页自由设计。
- 删除不需要的示例页通过明确页面操作；生成过程中使用稳定 page ID 跟踪，不能仅依赖会变化的页码。
- 页面副本不丢品牌素材，参考图按新主题重做，不能残留示例主题或占位字符串。
- 每页执行：读取最新 HTML → 修改 → 校验/合并 → 编辑器渲染 → 保存；根据检查结果再次通过 HTML 修正。
- `apply_html` 成功与持久化成功分开处理。任务不能在保存失败、视觉检查未完成或工具失败时报告整份完成。
- 废弃模板试生成中的 `sampleDeck/build_deck` 调用，复用正式项目生成入口。为试生成创建隔离项目，记录来源草稿版本，返回预览及可继续编辑的结果。
- 试生成按钮提供简短主题与页数；允许沿用默认测试输入，但不把默认值写成全局生成规则。
- 未打开编辑页时，产品负责打开并等待页面工具就绪；超时明确报连接状态，不让模型假装生成或反复要求用户猜测怎么打开。
- 20 页逐页或小批执行，记录已保存的页面、待检查页面、失败步骤与版本；失败后从现有项目继续，不重新初始化覆盖已完成稿件。
- 首版串行写同一文稿，避免多个代理同时覆盖版本；视觉只读任务若并行，结果必须绑定页面版本。
- 模型配置与插件可用模型权限继续由 Agent 统一控制，PPT 前后端不另设独立密钥/模型旁路。
- 视觉检查只能使用 Agent 授权且实际支持图像输入的模型；不能把只读结构的检查当作视觉检查。图片加载或视觉调用失败时保留待检查状态。

性能验收：记录 1 页/20 页模板导入、首次 HTML 可用、单字修改、复制页面、手改后刷新、导出耗时及主线程卡顿。按变更范围复用未变页面的投影与资产缓存，刷新任务合并处理、可取消，避免每敲一个字就全稿渲染。旧 HTML 必须即时失效；实际重新投影在一次编辑完成后自动触发，不能为了速度继续提供旧版本。首版先给真实测量结果和瓶颈，不凭空承诺毫秒指标，不把转换迁回服务器规避本地性能问题。

阶段门槛：试生成和正式生成调用相同路径，模板原件字节不变；5 页及 20 页能完整保存并恢复失败任务。

### 阶段 E：检查与修复闭环

检查应分工，不用“无溢出”代表“设计合格”：

| 检查 | 责任 | 失败处理 |
|---|---|---|
| 脚本/资源/CSS、身份、版本、用途权限 | 转换器与宿主 | 拒绝本次提交，保留上个有效版本 |
| 固定对象变化与品牌遮挡 | 规则检查 + 最终渲染 | 返回对象 ID、区域和原因，AI 改 HTML |
| 越界、文字裁切、异常换行 | 浏览器测量 + 编辑器实际渲染 | 返回对应节点，修复后重新检查 |
| 旧主题、残留占位、参考图未改 | 内容核对 + 视觉检查 | 返回页与元素，不能视为完成 |
| 构图、密度、层级、图文关系、图标是否有效 | 视觉模型检查真实页面图 | 给具体问题和修复意图；不强制某一种布局 |
| PPTX 交付还原 | 导出后重新打开；验收样例独立渲染 | 定位转换差异，不能仅美化 HTML 掩盖导出问题 |

- 检查对象是当前编辑器/导出结果，HTML 截图是对照；不能只看 HTML 就宣布 PPTX 正确。
- 审美沿用已引入的 Anthropic 原文指导，保持原文及哈希，不重新改写成固定卡片套路。
- 复杂图标用独立 SVG/PNG 或素材库，不使用可能缺字的 emoji/图标字体占位。
- 每次修复使该页旧检查失效。记录页面 ID、revision/hash、检查类型、结果与仍未解决的问题。
- 全部目标页必须被检查；20 页按批记录，不只看前几页。
- 设置有限修复轮次；超限报告具体未解决项，不无限循环、不虚称通过。轮次是执行预算，不是降低完成标准。
- 视觉结论与程序检测分开展示，如“结构检测通过，视觉检查尚有 2 页待修复”。

### 阶段 F：统一工具和 skill

更新 Agent 仓库 `skills/ppt-html-design/`、实际加载的安装副本、后端 `resource/ai_skills/ppt-master/` 及生成的页面工具声明。

- 检查主 skill 以及被引用的 annotate-template、realistic-samples、fix-template-layout、create-template、template-definition、template-designer 等子文档。
- 删除或明确停止引用旧 `apply_edits/build_deck`、SVG 建库目录、强制四角色、自动字段填充、等距填槽等冲突路径。
- AI 内容编辑统一 get_design/apply_html；模板制作模式额外允许受宿主控制的语义属性变化。
- 页面增删排序/复制属于结构工具例外；权限变化不能借此绕过。
- 区分固定品牌和可变参考图，不因 PNG 表示就认为可替换，也不因复杂素材就永久禁止明确的参考图替换。
- 更新能力声明、前后端工具 schema 和错误消息；增加检查防止未来再次出现“提示词要求不存在的工具”。
- 按 skill-creator 规范验证修改后的 skill；不复制或引入 Anthropic 完整 HTML→PPTX 生成流水线。

阶段门槛：从模板制作界面的按钮到实际传给 AI 的提示词、工具 schema、执行器行为完全一致。

## 7. 验收矩阵

### 自动测试

| 类别 | 必须覆盖 |
|---|---|
| 保护来源 | 母版 Logo、普通图片 Logo、组合矢量 Logo、品牌文字、固定背景 |
| 默认/例外 | 未标注图片保持固定；明确图片占位可替换；参考图可重做；不确定图像不能自行解锁 |
| 绕过保护 | 改 src、删节点、重命名 ID、改父组/祖先样式、图层、opacity、裁剪、前景遮挡；非法操作原子拒绝 |
| 语义写回 | 制作授权允许指定字段；生成模式拒绝改策略；仅修改说明也保存；过期确认失败 |
| 保存往返 | 只保存 PPTX 再打开，语义、保护、组、资产仍在；未知 OOXML 保留 |
| 差异合并 | 单字修改仅影响文本；颜色修改不改边距；flex 联动写回正确；无操作不重建 |
| 发布 | 单页/无角色可发布；未分类页不删除；坏资产/策略不合法拒绝；版本冲突正确处理 |
| 页面复制 | 副本有独立 ID，继承品牌/资源/策略；20 页导出无断链；重新排序仍准确定位 |
| 运行恢复 | 中途页面工具断开、保存失败、手改并发、重载、旧视觉结果失效；不覆盖有效稿件 |
| 试生成隔离 | 与正式生成同一路径；不修改模板；取消后不会继续往原稿写；保留用户测试产物 |

前端表单与任务测试、后端发布/权限测试、编辑器转换测试分别覆盖各自责任，避免仅更新快照或为了通过而删除断言。

### 实际产品验收

1. 使用联通品牌模板副本完成制作、标注、发布和选用；核对截图右上角两个标识保持原样。
2. 同一个模板版本生成 5 页快速样例和 20 页完整样例。主题可使用“联通产互为什么总加班”，不编造公司内部统计或事实。
3. 对无内容布局的页面自由设计，对已有布局页复用/轻改，对总结参考图按新主题重做。
4. 逐页查看编辑器 PNG，检查文字完整、背景与文本对齐、品牌位置、实际图标、内容密度、残留占位和旧主题。
5. 导出 PPTX 后重新导入编辑器；至少用一种独立 PPT 渲染器检查样例交付效果。查看缩略图后还需放大文字密集页。
6. 用户手动改一句话、移动一个可变对象，再让 AI 修改另一段，验证手工结果不被冲掉；撤销/重做后重复读取。
7. 模拟中途失败并继续，验证不会重建项目、重复页面、丢失已完成页面或报告虚假完成。
8. 保存验收证据：HTML 输入、输出 PPTX、逐页截图、页版本与检查结果、必要日志；不保存密钥。保留既有测试账号和用户要求留下的测试产物。

自动测试通过是必要条件；没有逐页视觉验收和实际发布→生成测试，不得宣称闭环完成。

## 8. 实施顺序与交付物

依赖顺序：A → B → C → D → E；F 随对应代码同步更新，在整体验收前完成。不要先只改提示词就上线，也不要先解除发布门槛而没有保护和生成路径。

建议以可回退的小批改动组织：

1. 语义契约、PPTX 持久化、目标模板夹具。
2. HTML 语义合并、保护规则、页面复制及其回归。
3. 制作界面和发布规则对齐。
4. 试生成/正式生成共用及失败恢复。
5. 检查闭环、skill 全面清理、实际样例验收。
6. 模板制作标准、部署包及上线验证。

每批说明具体行为、验证结果和剩余问题。不得用“测试全绿”替代未实施模块或未查看的页面。

最终文档交付：

- 模板制作标准：固定/可变/参考的含义、默认值、品牌规则、页面用途、真实示例与说明、PNG 预览和原素材、发布和试生成步骤。
- HTML 契约：可读/可写属性、制作与生成权限、版本约束、错误示例。
- 用一个成功转换的模板展示制作前后，给后续模板转换人员照做；不要求其理解 OOXML 或手写 JSON。
- 已验证能力与边界：当前 CSS 子集、复杂对象处理、组合变化、办公软件重新保存后的元数据情况。
- 验收记录和部署/回退步骤。

## 9. 部署与回退计划

目标环境沿用现有服务器部署体系；实际执行前读取当前端口、服务管理方式、部署目录和版本，不凭历史假设覆盖原服务。

发布单元包括 Agent/skill、PPT 后端（含工具声明与插件 skill）、PPT 前端（含编辑器/WASM）。编辑器是前端依赖，不无故新增第四个服务。

1. 本地完成构建、类型检查、相关回归和实际样例验收。
2. 备份现有发布包、必要数据库/对象版本及配置，打包时排除密钥和临时测试大文件。
3. 验证前后端契约兼容；如需数据迁移，采用可回退/向后读取方式。不要因升级批量重写历史模板。
4. 优先用测试端口验证整套新版本，确认模板制作到生成的闭环，再切换正式入口。
5. 版本不匹配时明确要求刷新客户端；不能用缓存旧工具继续执行。
6. 上线核对：新建单页模板、发布、试生成、正式生成、手改后 AI 续改、导出重开。
7. 回退同时考虑前后端工具协议与 skill，保留用户文稿及模板版本；不通过删除数据“恢复”。

本计划不执行部署。实施时遵循用户当时的部署指示；完成本地改造与验收不等于已更新服务器。

## 10. 给 ultra 的执行起点

按本计划实施模板制作与 PPT 生成闭环，先核对工作区现状，再从阶段 A 开始。重点确保 Logo 默认保护、模板语义可通过 HTML 受控写回、单页模板可发布、模板页复制继承保护、试生成和正式生成使用同一流程。保留浏览器侧转换和 PPTX 单一文稿持久化，不恢复填槽或 AI 原生 JSON 编辑。先完成一个联通品牌模板的 5 页与 20 页验收，随后写标准供他人转换其余模板。不要改动已有账号、密钥配置或用户测试产物；不要把本计划状态当成实现完成证据。

完成定义：模板上传/制作 → 发布 → 试生成 → 正式生成 → 检查修复 → 保存导出 → 手工编辑 → AI 续改全链路通过，品牌标识全程受保护，实际输出逐页审视，失败可恢复，文档与工具声明一致。
