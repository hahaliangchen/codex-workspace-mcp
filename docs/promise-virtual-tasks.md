# Promise 与虚函数调度设计

## 状态

本文是待实现的设计，当前代码**尚不支持**发起多个 AI 虚函数后继续执行父流程，也不支持 `Promise.all` 等待 AI 虚函数数组。当前支持的只是受限的并发只读操作，以及部分立即 await 的 Promise 链；不能用它们证明下面的并发行为已经实现。

已开始加入可序列化的内部 Promise 状态和 FIFO 续跑队列：可记录等待、成功或失败，以及等待中的续跑；重复结算不会重复入队，旧运行时快照缺少该状态时仍可读取。这个内部基础目前**尚未接入**编译器、JS 函数与闭包、微任务执行或宿主异步操作，不能用来执行通用 `then`、`await` 或并发虚函数。队列消费与外部回执的事务性恢复也尚未实现。

版本 13 起运行时快照使用内部堆，用稳定引用记录对象和数组；简单成员赋值、普通函数传递和暂停恢复已接入执行。版本 14 起变量存放在堆上的词法环境中（块级作用域）；闭包尚未接入函数执行；对象模型、垃圾回收和 Promise 值语义仍非完整 JavaScript 实现。

## 目标

虚函数调用返回待完成的句柄，父流程继续执行。调用启动时绑定实参和当时可见的上层变量快照，各调用的局部变量互相隔离。`await` 等待句柄，`Promise.all` 按输入顺序返回结果；失败进入调用处的异常处理，不得把并发调用悄悄改为串行。工具通过 `import` 从宿主库引入，仍经过原有权限与工具分发。

示意代码（当前尚不能执行）：

```js
import { read } from 'host:io';
/** @virtual 检查页面内容，返回检查结果。 */
async function inspect(content) {}
const paths = ['1.html', '2.html', '3.html', '4.html'];
const contents = await Promise.all(paths.map(async path => await read({path})));
const pending = contents.map(item => inspect(item.content));
const reports = await Promise.all(pending);
```

现有模型请求信号量默认允许 3 个请求同时在途，更多请求等待；它控制模型请求，而不是限制同一虚函数内工具操作。Promise 不需要引入用户可见的多 Agent 或线程概念。

## 实现要点

1. 编译器区分发起异步调用和等待结果，记录可序列化的句柄，不将句柄伪装成普通 JSON 数据；允许保存、传递并在 `await`/`Promise.all` 处消费。
2. 运行时同时保存父流程的指令位置、多个调用的标识、输入快照、状态及结果；调用发起后不切换走唯一的父执行帧。现有 `Runtime.pending` 和 `create_function_task` 只有一个暂停调用，需要扩展。
3. 宿主为每次调用建立独立的函数作用域，使用原有权限、工具、异常、自愈和模型请求队列；完成时只提交约定结果。父流程可以继续运行，等待的结果完成后才恢复。
4. 调用创建、完成和父流程推进必须有可恢复记录；重启后不能静默重复可能已执行的写入或模型调用。无法确定外部副作用状态时报告，而不是自动重放。取消时处理排队和运行中调用。
5. 多个调用可能访问同一文件；变量隔离不等于文件隔离，流程作者需要安排共享资源的写入顺序。

## 回家后的验证

- 用真实模型运行四个独立虚函数：观察前三个请求在途时，第四个在队列等待；确认完成一个后第四个启动。
- 在启动调用后、等待之前安排一个无依赖的宿主步骤，确认它确实先于 AI 返回执行。
- 让调用按不同顺序完成，确认 `Promise.all` 结果仍按输入顺序排列；让一个调用失败，确认 `await`/`catch` 得到错误。
- 启动后更改父变量，确认子调用看到启动时快照，各子作用域变量不泄漏。
- 在等待时中断并恢复，检查调用及结果不会重复；包含工具写入时特别检查副作用。
- 再对现有五页 HTML 项目运行检查，核对五页真实检查结果、导航断链以及报告；检查最终产物而不是只看模型报告。

以上验证应检查实际执行记录与产物。本文代码只是设计示意，不是已验证示例。
