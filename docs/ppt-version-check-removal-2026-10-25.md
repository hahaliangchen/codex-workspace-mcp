# 移除 PPT 版本拦截

按用户明确要求，移除 PPT 链路中因版本、预期版本或源快照哈希不匹配而拒绝操作的功能。历史序号和哈希继续用于记录、快照寻址、内容去重及实际文件完整性；不作为编辑或保存前提。

## 已移除

- 引擎 HTML 身份检查中的设计版本、source hash 格式/长度/相等检查；DOM 测量中的这两个字段必填要求。页面 ID、对象 ID、组关系、格式和固定元素权限仍检查。
- 测量结果合并、设计转换、页面桥接中的预期版本比较，以及读取/转换/标注确认期间因文档变化而拒绝结果的版本门槛。文档关闭、编辑器忙碌和对象权限仍按实际状态处理。
- 页面工具对 `expected_design_revision` 的必填、类型和数值要求；保留可选兼容字段，传入值忽略。HTML 的版本/hash字段也可省略。
- 自动保存的版本冲突状态、冲突异常、暂停/人工选择分支；前端 API 不再发送保存/恢复的预期版本。下载入口不再因导出版本与当前版本不一致而锁定或清空下载记录。
- Go 后端本地/对象存储保存、恢复、无状态转换、旧 SVG 写入、模板预览和模板发布中的预期版本比较及 409 冲突返回。旧版参数缺失或格式错误也不阻断这些接口。
- 模板选择的期望 hash 匹配和系统模板描述发生变化时的版本拒绝。仍能定位实际存在的历史模板资源，不改模板访问权限。
- 可选视觉记录/进度汇总和缩略图任务中的版本过期门槛；检查证据本身、页面归属和真实结论仍保留。

所有保存按实际提交/事务顺序处理，后提交内容可以覆盖先前内容。对象存储在事务中原子递增保存序号；相同内容重试直接返回已存在的保存记录，实际 IO/数据库错误继续回报。没有改通用 Agent 的任务、上下文或用户方案确认机制。
