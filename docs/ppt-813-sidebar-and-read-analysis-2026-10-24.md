## 失败与重试如何叠加

1. **只读元数据被改写。**16:41:43，第 2 页将原节点的 `data-name` 从 `Rectangle 9` 改成 `TextBox 9`，被 `TEMPLATE_HTML_METADATA` 拒绝。这次拒绝属于保留原属性要求。
2. **保存回执与已保存状态不一致。**16:42:08 提交第 2 页，约 20 秒后返回 `invalid connection`；已有项目事件显示 16:42:18 已产生稿件版本 4。之后读取报告版本冲突。16:43:20 出现来源为 user 的版本 5，hash 与版本 4 相同；不能仅凭这条事件推断用户具体点过哪个按钮。
3. **实际排版错误后出现无效修复。**16:44:10 先有文字底部越界 5 像素。16:44:47 至 16:47:18，六次提交因同一文本节点左侧越界 1 像素被拒绝。文本框 x 从 82、78、90、100、120 调到 125，文字墨迹的最左 x 始终是框 x−1。期间也改字号、文案和宽高，但这些修改没有改变文字与框左缘的相对位置。
4. **最后改对方向，又遇到连接错误。**16:47:37 的 HTML 才给文本框加 `padding-left:8px`；它没有再返回前述越界错误，而在约 20 秒后返回 `invalid connection`。不能据此认定页面已经持久化成功。随后 16:48:04 至 16:52:49 又有 19 次 `get_design`，均返回版本冲突；换读大纲、渲染和版面检查也没有解除冲突。

引擎 `src/design/measure-dom.ts` 按浏览器测得的实际字形墨迹检查，横向允许 0.5 像素、纵向允许 1 像素。日志中的左越界 1 像素确实触发该阈值。提交 HTML 没有左内边距，平移整个框不能消除相对框边缘的字形伸出。仅凭日志不能判定为模板坏了，也不能证明该阈值对所有字体均合适；字体边缘与判定策略需要独立核实，本次未更改引擎阈值。

现有 PPT skill 要求拒绝后读当前 HTML 再修复，能解释一部分失败后的重读，不能解释没有提交、没有版本变化时连续读五次。保存端已有“连接丢失后检查是否已提交”的恢复代码，但本轮仍未恢复成功；不能把这个问题简化为“没有写任何恢复逻辑”。后台同时有其他接口的 `invalid connection`，说明连接问题不限于这个 PPT 工具。
