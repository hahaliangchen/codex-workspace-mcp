# Agent 设计

更新：2026-10-29。**本文是当前设计的唯一依据。** 代码、面向 AI 的提示词、Skill、测试和其他文档与本文冲突时，一律按本文修改。标注「待实现」的部分，代码还没有做到；其他文档里的「当前」「已实现」只代表写作当时的状态。

## 1. 出发点

不考虑上下文容量时，最稳、最有效率的 Agent 就是一个朴素循环：消息按顺序堆叠 → 调用 AI → 执行它的工具调用 → 重复，AI 不再调用工具时结束。

问题只在于上下文容量有限。动态压缩、删减上下文会让实现变复杂、问题频出；遇到一种意外就加一种状态，最终成为死板的状态机。本设计不压缩上下文，而是借用编程语言的**函数作用域**来分流和裁剪：

- 函数内部的数据在函数返回后销毁；
- 调用方只知道调用过它、拿到了返回值，不必知道细节。

所以 AI 做事时先用 JavaScript 写流程，难以用代码确定的部分声明为**虚函数**，由宿主在运行时交给 AI 实现。每次 AI 工作都在自己的函数上下文里进行，上下文随函数返回而释放；最内层的叶子虚函数就是上面的朴素循环（层级见第 3.1 节）。这也利用了 AI 极其擅长编程这一点。

## 2. 流程代码就是 JavaScript

- AI 写的流程是普通 JavaScript：顺序、分支、循环、函数、闭包、`async`/`await`、`Promise`、`try`/`catch` 都按 JS 语义理解，不另造流程语言，也不要求 AI 记一套额外规则。
- 当前执行器是 SWC 解析、Rust 自建的 JS 子集虚拟机（见 [执行语言手册](agent-program.md)）。子集的缺口应向真实 JS 补齐，而不是在提示词里教 AI 绕开。
- 是否改用 Node/V8 仍是待验证方向，不在本文范围内决定。

## 3. 虚函数：唯一的 AI 入口

**只有虚函数能调用 AI；其他函数必须是完整实现的代码。** 普通函数里不能只写注释等 AI 补全，也不能让宿主替它猜实现。

虚函数用 `/** @virtual */` 标记，函数体只有注释，即这个函数的规范：职责、参数含义、返回结构、不做什么。和现实编程语言里的虚函数一样，它定义能力的期望，实现留给后面。

```js
import * as io from "host:io";

const pages = await Promise.all(list.map(item => designPage(shared, item)));

/** @virtual */
async function designPage(shared, page) {
  // 依据 shared 中的实际材料设计本页。
  // 返回 {content:string}；不写文件。
}
```

### 3.1 两层边界

层级由**虚函数声明在哪一层源码里**决定，不由运行时状态决定：

| 层 | 是什么 | AI 怎么工作 |
| --- | --- | --- |
| 主脚本 | 主任务中 AI 回复的 ```js 代码块 | 主任务 AI 写出整份流程，宿主编译并执行 |
| 第一层虚函数 | 主脚本里声明的虚函数 | AI **写 JS 代码**作为它的实现；实现中的普通函数必须完整，需要 AI 的部分只能再声明虚函数 |
| 叶子虚函数 | 第一层实现代码里声明的虚函数 | **最简工具调用循环**，不能写代码，也不能再声明虚函数 |

- 第一层虚函数总是用代码实现，不能改为直接跑工具循环。简单的任务就写简单的实现。
- 虚函数可以像普通 JS 一样嵌套声明在另一个函数体内；它属于哪一层，仍看它写在哪一份源码里。函数头的 `@virtual` 只标记它自己，不会让外层函数变成虚函数。
- 叶子是整个设计里唯一的「纯循环」，也就是第 1 节的数组迭代式 loop。
- 提示词给的书写方向只是建议，只有大问题才禁止。第一层的代码本意是用流程表达做法；AI 若愿意直接把正确结果写进代码，也可以。

### 3.2 作用域和上下文

- 每次调用 AI 都有自己的上下文。主脚本是主任务的对话；虚函数（第一层编码和叶子循环）只有自己的函数签名、规范注释、**实际传入的参数值**，以及已加载的技能说明，调用方的对话和变量都不会带进来。
- 函数返回后，它的上下文整体释放；调用方只拿到返回值。
- 需要的数据由调用方**作为参数显式传入**，不让 AI 去读取调用方的变量（废弃 `scope_variables`、`host.read_scope`）。
- `async` 虚函数在调用时拿到实参；调用方之后的变化不会同步过去。
- 返回值是跨作用域的唯一通道。调用方若发现缺信息，应修改虚函数的规范（参数、返回结构），而不是让宿主保留内部过程。
- 调用方代码负责检查返回值是否满足约定；不满足就不能当作成功。

## 4. 工具是库

- 工具方法以库的形式提供，在源码中 `import * as io from "host:io"` 引入，返回工具的原始 JSON。
- 宿主**不在每次请求里发送完整工具列表**，以减少工具定义带来的上下文开销。第一层和叶子已经如此；主任务的请求仍附完整列表，按第 9 节第 5 步改掉。
- 写代码的 AI（主脚本、第一层）拿到库和方法的简要索引，需要时用 `read_tool_contracts` 查方法契约。第一层只能调用这一个工具，其余都要写进代码。
- **叶子的工具范围 = 声明它的那段源码 import 了的库方法。** AI 写实现时 import 什么，本身就是对这些虚函数需要哪些能力的预期。
- 叶子循环里固定保留 `find_library_methods`，按关键词查找方法。找到的方法只加到**这一次循环**的范围里（由这次循环自己的消息推出），随函数返回消失，不写入持久状态；只能搜索，不提供「列出全部」。
- 查找和 import 都不扩大权限，权限检查发生在实际调用时。

## 5. Promise 取代子 Agent

- 并发用 `async` 虚函数加 `Promise.all`／`Promise.race` 等表达，可以并发，也可以不等待、先做下一件事。
- 不存在单独的「子 Agent」「任务分支」概念；一次虚函数调用就是一次 AI 工作，结果就是返回值。
- 模型调用的并发数由宿主的队列限制。

## 6. 错误：统一走异常

- **编译错误**：源码在任何操作前整份编译；失败时什么都不执行，带行列和原因的诊断交回同一个 AI，由它重写完整源码再提交。
- **运行时错误**：按 JS 语义沿调用栈 `throw`，由流程代码的 `try`/`catch` 决定重试、换做法或继续上抛。
- **第一层实现的运行时错误先交回它的作者。** AI 写的代码不可能次次正确：实现代码没有捕获的错误，连同它已完成的写入，交回写这段实现的同一个 AI。AI 可以重写完整实现（从头运行，不重做已列出的写入），也可以回复 `{"$task_error":…}` 放弃，这时错误才抛给调用方。普通函数的错误照常直接抛出。
- **上下文超限：不压缩，直接抛错。** 叶子循环的下一次请求放不进上下文时，叶子以错误结束，异常回到能写代码的第一层；第一层把工作拆得更细后重新调用，或者继续上抛。错误中带上叶子已经完成的副作用（例如已写入的文件），避免上层重复写入或覆盖。
- **主窗口放不下时，交给 AI 自己处理，不暴露给用户。** 放不进剩余空间的结果不交付，原件存为资产，AI 收到 `MATERIAL_OVER_CAPACITY`（大小、剩余空间、资产编号），自行决定按页读取、释放已加载的材料或换一种做法。
- 外部写操作结果未知时不自动重放。

## 7. 副作用边界

作用域隔离的是上下文，不是外部世界。并发的虚函数可能写同一个文件，所以宿主为 Agent 的写入保留按文件的基线；遇到外部修改或并发冲突时停止并保留双方内容（`managed_files`）。这属于副作用边界，与上下文管理无关。

## 8. 已废弃，不得恢复

以下机制与本设计冲突。代码中仍存在的部分按第 9 节逐步删除，期间不得再扩展：

- **上下文折叠**：按容量把旧对话折叠成摘要（原 `step_context`，2026-10-30 已删除）。资产存储及 `read_asset`、`release_assets` 等工具不在此列：它们是 AI 自己处理大材料的手段，保留。
- **任务/步骤/saga 流程**：任务树的步骤节点和结束节点、结束节点持有迭代器、模型可调用的 `create_task`／`branch_task`，任务板（`read_task_board`）与任务定义、计划确认（`main_task_anchor`）。2026-10-30 均已删除；保留下来的是精简后的函数帧。
- **要 AI 额外记住的特殊 API**：`invoke_library`、`define_task_body`、`read_program_guide`、`host.read_scope`／`scope_variables`，以及要求 AI 手动调用的 `execute_program`、`check_program`。
- **完整工具列表**：每次请求都附上所有工具定义。
- **适配层**：把虚拟机执行伪装成旧式工具往来，以便沿用上述机制（2026-10-30 已删除）。
- **用状态驱动流程**：状态标记、完成确认、计划工具、证据/阻塞校验、催促提示。

2. ~~删除上下文折叠~~（2026-10-30 完成）：`step_context` 整个删除，宿主不再自动折叠任何上下文。资产逻辑保留。
3. ~~删除任务树、任务板和计划确认~~（2026-10-30 完成）：
   - 任务板与计划确认已删除：AI 写的程序本身就是任务清单，“这个任务做哪几件事”的面板可以从程序结构和函数调用事件得到。
   - 任务树已精简为函数帧（模块 `function_frames`）：每次主请求和每次函数调用各是一个帧，帧上记录调用方（`metadata.caller`）、函数名与契约、实参、源码调用位置（`metadata.call_site`）、状态（`running`／`done`／`failed`）和结果。“Round N”步骤节点、结束节点和迭代器都已去掉；事件直接标记到所属的帧上。帧的开始和返回仍以 `task/node_*` 事件发出，以后的 Flow 展示可以直接由这些帧画出。数据库表名和事件名暂未改动，以兼容已有会话。

4. 删除特殊 API，改为参数显式传入。`host.read_scope`／`scope_variables` 已于 2026-10-29 删除，虚函数窗口也不再继承调用方的变量；主窗口专用的 host 方法（资产、任务板、会话历史、项目笔记）不再出现在虚函数的库里。
5. 停止发送完整工具列表。
