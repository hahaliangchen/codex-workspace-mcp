# 通用 Agent 设计：流程伪代码、函数作用域与插件边界

> 阅读前先看 [设计与实现入口](agent-design-guide.md)。本文混有不同阶段的方案；旧工具调用方式和语言版本不代表最新设计。

更新日期：2026-10-29。本文记录通用 Agent 的设计边界、当前实现及验证结果。第 1.1 节是设计原则；第 1–8 节描述当前设计（流程语言版本 14：JS VM、词法作用域与闭包、Promise 与 async 虚函数并发，见 [js-runtime-design.md](js-runtime-design.md) 与 [agent-program.md](agent-program.md)）。第 9 节起是按日期保存的历史记录，其中的 fork/join、子 Agent、Git 工作树整合及当时的版本限制均已退役或被替代，不代表当前实现。

本文作为后续维护通用执行层的设计依据。早期文档中的规划闸门、步骤必须返回专门协议、宿主替业务创建节点、每轮强制折叠、两次无工具回复才结束等方案，不能直接作为当前实现要求。修改前应对照本文和实际代码；有意改变这里的执行语义时，同步说明原因、更新文档及回归测试。

## 1. 设计目的

Agent 是通用执行器。用户提出目标，模型结合适用的技能与工具决定如何完成；宿主负责让调用持续推进、记录事实、装配上下文，以及在函数调用之间挂起和恢复。

核心对应关系如下：

| 程序概念 | Agent 中的对应物 |
| --- | --- |
| 主函数 | 一项用户授权工作的主任务 |
| 临时函数 | 为独立局部工作创建的串行子任务 |
| 函数参数 | 有序实参绑定为命名局部值，包含要求、材料或稳定资产引用 |
| 父作用域变量 | 父任务准备好的技能、工具、工作区信息、公共材料和其他可用结果 |
| 局部变量 | 当前函数仍被引用的 JSON 绑定与 AI 工作上下文 |
| 调用与挂起 | 程序执行 `helper(args)`，宿主保存调用方工作帧并进入函数作用域 |
| 返回值 | 子任务结果摘要及保存结果的资产引用 |
| 迭代器 | Runtime 保存函数帧、PC、变量和挂起效果 ID |
| `finish` | 记录函数返回并恢复调用方程序；不维护另一条任务链 |
| 执行步骤 | 宿主对一次实际模型请求及其回复、工具交换的记录 |

生成器和 redux-saga 的调用、挂起、返回思想用于解释控制流。当前实现由 SWC 解析固定 JS 基础语法子集的普通函数结构，Rust 通过循环、工作帧和持久化迭代器兑现调用语义；不运行任意 JavaScript，也不依赖 redux-saga 库。

### 1.1 流程和普通计算由宿主执行，智能判断显式调用

最新原则：普通函数、JSON 数据、常见循环和运算符表达流程；宿主确定性计算普通表达式，不把 i+1 或条件比较交给 AI。for/while、break/continue、三元和模板字符串降低到已有执行结构，不因模型采用常见写法就拒绝编译。当前范围与值规则见[执行语言手册](agent-program.md)；目标是让 AI 写真实 JavaScript，采用 Node 等技术路线仍需验证。

需要内容理解、生成或业务验收时，声明具有注释职责和返回契约的任务函数。例如 const check = inspect(artifact, requirements)，AI 使用真实工具证据返回 {passed,evidence,issues}，宿主执行 if (!check.passed)。artifact !== expected 只比较 JSON 数据，不能同时解释为“业务质量不合格”。计算类型错误明确抛出，不自动请求 AI 解释。

宿主负责调用、返回、作用域、迭代、确定性表达式、持久化、权限与取消；AI 负责显式任务的智能处理。业务流程与验收标准仍来自用户、技能和插件。相同输入及相同外部返回值具有相同控制流，不代表外部工具、AI 判断或整个业务成为确定性的。

## 2. 谁决定什么

| 参与者 | 职责 | 边界 |
| --- | --- | --- |
| 用户 | 提出目标、约束、范围变更和必要的确认 | 授权来自用户，不能由工具可用性或历史材料扩大 |
| 模型 | 理解需求、采用技能、选择工具、组织子任务、消费结果、验证并报告 | 不需要维护宿主内部状态机，不把工具成功等同于目标完成 |
| 技能／业务插件 | 提供业务流程、生产规范、工具契约、业务条件和验收要求 | 不改变宿主权限；通过通用接口接入执行器 |
| 宿主 | 工具分发、作用域、调用与返回、迭代、持久化、容量控制、权限、取消、通用异步结果交付 | 不替业务制定生产步骤、页数、版式或验收标准 |
| 工具及业务后端 | 执行具体操作，返回实际产物、状态、错误和条件是否具备 | `accepted` 只表示已受理；结果必须如实表达，不能让模型猜测是否完成 |
| 界面 | 展示对话、调用图、任务进度、确认入口和产物 | 图上的结束状态不能冒充业务验收结论 |

宿主可以提示“当前任务是什么、已有哪些输入、返回到哪里”；不能在通用系统提示中要求某业务必须先初始化项目、固定创建几页、使用某种布局或进行某类内容审核。

## 3. 执行主线

### 3.1 唯一执行主线

```text
用户请求 → 宿主建立主任务 → AI 输出顶层 JS → 宿主编译执行
运行 Runtime：
    普通计算／分支／循环 → 宿主确定性推进 PC
    工具效果 → 原权限分发，保存原始回执，再恢复同一 Runtime
    函数调用 → 以真实实参进入局部作用域
        普通函数 → 执行代码
        @virtual → 当前 AI 完成职责，或补写同名函数
    async 虚函数 → 立即得到 Promise，各自在独立 AI 窗口并发运行；await／Promise.all 收齐返回
    helper 返回 → 释放局部窗口，把 JSON 值交回原调用位置
    顶层代码结束 → 保存结果，结束主任务
```

主任务由宿主建立，AI 无须手动调用 `create_task` 或 `execute_program`。子函数、步骤与返回由程序运行时记录；内部保留任务创建机制并不表示 AI 需要调用该工具。无需工具的普通问答可以直接回复。

### 3.2 串行顺序只有一个来源

普通的函数调用和循环表达串行顺序；函数返回后从挂起的 PC 继续。原先 `create_task({tasks:[...]})`、`next_in_chain`、手动步骤以及自然语言委派的执行路径已删除。任务图记录已经发生的调用，不是另一台调度器。

### 3.3 动态任务与执行步骤

任务可以在执行中创建。遇到需要单独处理的工作时，当前函数调用一个临时函数；后者返回后，恢复遇到该工作的函数。主任务及全部步骤不必在一开始规划完。

已明确的多个目标写成顺序函数调用或循环。尚需 AI 判断的局部工作用虚函数，在执行到该处时直接处理或补写，不默认分叉并行。

一次模型调用对应一个宿主执行步骤。步骤记录输入、回复、工具调用、返回及引用；它不是新的函数作用域。工具返回后在同一任务里继续调用模型，不会因此丢失该任务的材料。

### 3.4 待办清单与子任务

待办清单是对工作的安排，子任务是有独立局部上下文的执行单元，两者不要求一一对应。

适合创建子任务的情形：局部工作有清楚目标、需要自己的材料或探索过程，并能向调用方交回可用结果。简单的连续读写或同一目标内的常规操作，可以留在当前任务。

拆成几个子任务、按页面拆还是按生产阶段拆，由模型结合用户要求和技能决定。宿主不根据交付物数量固定拆分，不把测试案例中的数量写进通用提示词。

### 3.5 当前实现：常见基础语法与持久化指令

主任务准备缺失技能／工具契约后，AI 输出覆盖完整工作、验证和交付的顶层 JS，宿主提取并执行。SWC 使用 JS 解析模式；编译器整体检查源码，再降低成可持久化指令，在可序列化堆上的 JS VM 中执行：块级作用域、闭包与函数值、解构、展开、switch/finally/标签跳转、async/await 和 Promise 均已支持，数组回调由 JS 预置库以可恢复帧执行。生成器、类／this 与非工具模块仍拒绝。

普通函数调用在 Runtime 局部函数帧内执行，不创建 AI 任务节点；工具调用是步骤。显式标记 @virtual 的空函数创建独立 AI 任务上下文并交给执行 AI，普通注释不自动执行；虚函数不允许占位 return。后者可 define_task_body 去掉当前标记、补写实际函数和更细的 helper，不重建 main。公共材料及各分支职责显式传参，已知循环由代码推进；需要并发时把虚函数声明为 async，用 `await Promise.all` 收齐结果。fork/join 已退役，新源码中会被编译拒绝。顶层代码结束即结束流程，helper 返回恢复调用方，finish 不额外询问模型。工具只使用固定库方法：内置 io 绑定文件工具，插件在清单声明库名，参数与返回契约生成 TS 风格头文件。发布与编译共用权限过滤目录；规划请求不重复发送业务 JSON schema，注释任务用 invoke_library 传输相同方法名。工具可通过 import 使用命名别名；宿主编译结果持久化，实际调用仍受原权限和插件边界约束。

### 3.6 表达式与智能任务的边界

普通算术、比较、布尔逻辑、模板转换和公布的数据方法在 Rust 中直接求值，无模型任务。短路／三元只执行选中分支，操作数、实参和字段按顺序冻结值。循环 continue 正确经过更新或条件，跳转离开 try 时清理跨越的 catch 栈；位置和局部值随挂起效果持久化，恢复消费已有回执不重复更新。

智能判断必须通过有说明和输入的任务函数返回 JSON；证据随该任务回执和实际工具历史保存。没有运算符专用 value/evidence 协议，没有未知名字／数据方法的 AI 兜底。当前值和条件语义以版本 14 的实现与执行语言手册为准。算术类型错误和除零等沿已有异常路径传播。旧 Semantic/Ai 类型和相关执行／恢复分支已删除；旧语言现场不能续跑，原始记录仍可查询。

## 4. 共享环境与局部上下文

### 4.1 公共准备放在调用方

多个子任务要复用的能力和材料，应先在它们的调用方准备好。常见例子是工作区信息、适用技能、文件工具、公共规范和输入资料。

技能激活由当前作用域继承，工具目录按权限与插件归属直接发布，无工具组加载／卸载状态。需要共同使用的材料在父函数准备好，以真实实参传给各个函数。

### 4.2 可见性规则

| 信息 | 当前函数 | 它的子函数 | 兄弟函数／调用方恢复后 |
| --- | --- | --- | --- |
| 调用方已经准备的工具和技能 | 可用 | 继承可用 | 调用方仍保留原能力 |
| 调用方的公共资料与成功结果 | 可用 | 在容量允许时提供正文，否则提供保存版本的引用 | 调用方自己的值不被子任务工作记录替换 |
| 当前函数新读取的局部材料 | 可用 | 可供嵌套子函数使用 | 默认不注入局部正文 |
| 当前函数新激活的技能 | 受当前权限约束 | 嵌套子函数继承 | 不自动改变父／兄弟的激活记录 |
| 当前函数的探索对话和已解决报错 | 留在本函数过程记录 | 不整份继承；必要证据通过输入或引用提供 | 不自动复制到返回后的工作上下文 |
| 明确返回的结果与产物引用 | 保存 | 可作为后续输入 | 通过返回通道交接 |

这是一种父作用域读取与局部隔离的语义。实现中采用工作帧、保存的结果快照和引用装配，不是跨帧共享一个可以随意改写的内存对象。写入真实文件、页面或其他外部资源仍会产生实际副作用；局部上下文释放不会撤销这些写入。

### 4.3 当前实现怎样提供父变量

当前形参由 program_task_input.bindings 提供一次；其他真实可见变量保存在 scope_values，scope_variables 只公布名称、类型和大小。需要某个仍可见值时通过 host.read_scope 按字段只读获取。源码通过实参表达依赖，不从历史调用、回执和资产目录重组“父变量”。

普通与并发函数都继承有效技能、权限边界和可见变量快照，不继承父工作对话。固定参数超过硬容量时明确失败；长材料应作为资产引用或分段处理，而不是默默省略参数。

父值是已保存版本，并非文件或后端的实时订阅。外部资源可能变化时，应按实际需要显式读取当前版本或刷新；减少重复初始化不等于禁止有目的的复查。

### 4.4 返回与释放

子任务返回摘要和保存结果的引用。输入材料不会被重复列为子任务新产物。调用方恢复自己的工作帧，接收返回值；子任务的局部活动窗口释放。

释放的是活动上下文，不是删除原始历史、快照或产物。需要进一步核验时，可以按引用回查。若某个结果要成为父函数后续可使用的数据，应通过返回通道交接，并按需读回，不能靠复制整个子函数过程实现。

## 5. 上下文策略与主任务记忆

### 5.1 目标由系统保存，进度读取真实记录

持续确定“现在在做什么”，依靠持久化目标、当前任务路径、输入和已确认的任务定义，不依靠模型从过程摘要中猜回原始任务。

已确认的主任务定义与计划若存在，通过独立于可折叠工作窗口的系统层装配；当前任务路径、执行位置和资产索引由宿主提供。原始用户请求也保留为执行输入。当前实现并非只发送结构化目标而完全不发送用户原话。

普通聊天、情绪表达、一次临时检查、暂停或继续，不应自动变成新的永久主任务目标。用户插话可以影响当前执行；已经保存并等待用户确认的定义或计划，只通过明确的界面决定生效，不能从“好的”等聊天文字猜测确认。

创建普通执行任务，不要求额外增加一次用户审批。需要用户决定的边界来自现有权限、已保存的确认流程或业务技能的实际要求。

完成了哪些操作、哪些产物已经保存、哪些检查通过，应从任务事件、工具返回和业务系统状态读取。模型说“完成了”不能代替这些事实。

### 5.2 按容量折叠，保留恢复入口

当前新步骤执行路径采用确定性的容量折叠：

1. 容量足够时保留完整工具交换，不在每轮无条件清掉前一步。
2. 先扣除固定指令和函数输入，在剩余工作容量的 80% 触发，从最旧已完成步骤折为操作记录，尽力回落到剩余容量的 60%。
3. 原样步骤已经折完仍有压力时，再把最旧操作记录合并为带历史范围的前缀记录。
4. 系统指令、原始用户输入、固定／显式输入、钉住的规则和最新交换受到保护。同一资产相同正文去重。
5. 25% 是尽力目标，不是容量保证；最终仍检查整份请求的硬上限。材料过大时保留原件引用，分页读取，而不是静默截断后声称已经读完。

历史按引用回查不等于重放工具操作。`read_asset` 读取保存版本，`refresh_asset` 显式读当前支持刷新的本地文件，`read_session_history` 查看原始记录。

当前机制不是“模型自动理解每条过程记录的重要程度后做语义筛选”。固定目标、作用域隔离、容量折叠和引用恢复共同限制过程上下文的增长；不能宣称任意长任务都不再需要容量管理。

主任务结束后的跨轮记忆按任务索引保存目标、最终摘要和节点引用；新的任务不默认加载过去任务全部工作过程。

## 6. 宿主与业务插件的边界

### 6.1 插件激活

用户进入插件页面或使用其绑定会话时，宿主激活对应插件及声明工具。有技能说明时，在模型执行前装配其业务指令，并在该插件会话持续使用；不要求模型每一步重新发现、加载相同技能。

插件可以没有 MD／技能说明。没有说明不应被当作加载失败，也不能据此虚构一个业务流程。模型使用实际声明的工具与已有信息。

技能中的逻辑工具名按照插件提供的映射对应实际发布名称。宿主负责分发与作用域检查；不能因为名字相近，把插件工具替换成另一个宿主工具。

### 6.2 业务事实由插件提供

是否已经初始化、输入是否齐备、产物是否存在、能否执行后续业务操作，由插件工具返回明确事实。宿主交付结果；模型遵循业务技能消费结果。

宿主不维护一个特定业务的影子状态机，不根据对话猜项目 ID，不为了推进通用任务图伪造业务条件。页面数、设计步骤、数据绑定、模板规则、布局和业务验收要求，都属于具体插件或任务输入。

### 6.3 通用异步交付

插件返回受理中的任务时，宿主记录原调用、后台任务 ID 和所属执行步骤，通过同一插件的通用查询契约获取结果，并交回正确作用域。`accepted` 不等于业务完成。

当前作用域存在待收集的异步结果时，无工具回复不会绕过这些结果直接交付最终答案。收到结果后，模型在正常执行中消费它；这与无实际结果变化、仅再问一次“是否完成”的收尾确认不同。

宿主可以记录和交付后台状态，不应替插件判断某类业务初始化是否就绪。业务条件不具备时，插件应明确告知，而不是让通用 Agent 内置专门的业务判断。

## 7. 返回、验收与异常

`finish` 表示当前函数执行返回，不是宿主对业务成功作了认证。当前存储中的任务 `done` 应按这个范围理解；执行结束与业务产物通过验收应分别展示。

| 情形 | 处理原则 |
| --- | --- |
| 普通工具成功 | 结果留在当前作用域，继续模型执行；不因此宣布目标完成 |
| 普通工具报错 | 交回原始错误，由当前模型结合任务决定恢复或报告；不自动新建“修复任务” |
| 子任务返回阻碍说明 | 保留原说明和产物引用；不把它改写成成功结论 |
| 函数调用返回 | JSON 返回值恢复原程序，后续条件和调用决定下一步，不靠摘要猜测控制流 |
| 下一工作帧无法建立 | 错误交回当前程序，未捕获则停止，不伪造已执行 |
| 用户暂停或取消 | 响应控制，保留必要现场和原始记录；不把暂停写成永久业务目标 |
| 必要用户确认尚未完成 | 保持相关任务现场，等待明确决定；不靠普通聊天猜测批准 |
| 模型或网关失败 | 记录实际失败阶段；不当作完成、不循环重试没有证据的副作用 |
| 进程中断，工具完成情况未知 | 恢复已有结果；缺少结果时明确标记未知，不自动重放写入、上传等操作 |

模型仍需按技能检查真实产物。工具契约可以确定地验证必要条件；视觉、美观度、内容覆盖等判断需要相应实际证据。执行图返回不能替代这些检查。

串行子任务不等于并发。默认使用串行执行；需要几份 AI 工作同时进行时，把相应虚函数声明为 async 并用 `Promise.all` 等待，每个调用是独立 AI 窗口，同时运行的数量受模型并发槽位限制。不因为存在待办清单就并发；并发调用各写各的文件，共享文件在收齐结果后由父流程统一写入。

## 10. 后续修改必须守住的边界

1. 业务生产流程继续由技能和插件给出，不进入通用宿主提示和调度代码。
2. 父任务准备的公共值向下可用；子任务的局部过程不自动向上或向兄弟传播。
3. `finish` 只交接返回值并推进迭代器，不新增一次模型复核或业务审批。
4. 已提供的结果与材料应直接复用；查询历史用于补缺失证据，不是每次开工的固定仪式。
5. 动态任务保持按需；不强制每次工具调用创建任务，不强制每条待办创建一个作用域。
6. 任务结束不等于业务验收通过；所有成功声明应有实际产物和工具证据。
7. 容量不足保留引用与原件，不通过静默省略目标、材料或结果来假装流程正常。
8. 原有权限、插件归属、取消和明确用户确认仍有效；变量继承不能扩大授权。
9. 代码形式用于表示流程；业务语义交给 AI，宿主不因描述性比较、断言或方法名而不断扩张为语言虚拟机。

历史设计对照可查 [2026-10-23 图迭代方案](graph-iterator-agent-2026-10-23.md)、[2026-10-25 容量折叠记录](agent-step-context-capacity-fold-2026-10-25.md) 与 [两级容量兜底](agent-context-range-fallback-2026-10-25.md)。这些是演进记录；其中与本文冲突的旧调用协议、阈值或完成机制，不作为当前执行规范。


## 11. 函数任务与当前函数补写验证（2026-10-26）
