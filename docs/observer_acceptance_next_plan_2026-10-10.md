# Observer 用户要求验收计划和 Agent 测试任务

日期：2026-10-10。

下一步让 Observer 在每轮执行结束后检查用户要求是否完成。发现有依据的遗漏或实现缺陷时，将具体问题交回 Organizer，安排补齐并再次验收。过程得失和效率建议作为附带复盘，验收结论以实际结果为依据。

## 当前实现状态

已完成的基础：

- Observer 仅在执行结束后复盘，不在运行中观察、派发建议或参与调度；取消或中断不启动新复盘。
- 原始正文和图片保留，消息携带执行者、轮次、步骤、任务及节点身份、顺序、时间、调用关联、失败标志和复盘状态。
- Worker 交接、Organizer、Observer 和历史查询使用相同来源记录，各角色读取范围仍按其职责确定。Worker 接收 Organizer 的命令、必要输入和本次执行消息。
- 完整角色请求保留，Observer 可按需读取 Worker、Organizer 当时实际收到的上下文。续聊恢复保留工具失败状态；内容相同的上游返回按工作编号关联来源。
- 复盘显示在聊天中，不自动写入记忆。

本轮验证为 324 项测试通过、0 项失败、5 项真实调用测试未运行；前后端构建通过，本地服务已更新。此次修改后尚未重跑真实 PPT 任务。

**自动验收后触发补齐尚未实现。** 当前 Observer 的结果只保存并展示，不会自动调用 Organizer 开始下一轮。

## 下一步执行流程

1. Organizer 执行用户任务，认为本轮工作已完成时，提交实际结果供 Observer 验收。
2. Observer 对照当前有效的用户要求，读取本任务原始过程，必要时读取代码、图片及实际角色请求，核实要求与结果是否一致。
3. 满足要求时，交付验收结论，再附上过程得失与下次可改进之处。
4. 存在具体遗漏或实现不符时，Observer 将未满足的用户要求、原始证据和问题说明交给 Organizer，并明确请求继续处理。
5. Organizer 接收这次原始交接，安排所需的补齐任务，复用已有成果和仍可用的资源。补齐后再次交给 Observer 验收。

自动补齐沿用当前会话和用户目标，保留前轮操作及验收结论。用户改变要求时，以最新有效要求为准，不能将旧轮次的限制继续当成当前指令。

宿主负责传递原始消息并执行角色明确发出的调用。是否满足用户要求、是否需要补齐、具体补什么，由 AI 判断；宿主不通过汇总关键词、评分或另一套事实摘要决定业务完成情况，也不新增固定补齐轮数。

## Observer 验收时检查什么

验收先回答“用户要求做的事情是否实际完成”，再解释过程质量。每个未完成项都应能对应到具体用户要求和原始证据。

- 区分用户要求、Organizer 安排、Worker 实际操作和角色事后声称的结果。
- 核对实际成果，不能仅凭 Worker 或 Organizer 的“已完成”总结验收通过。代码任务需检查相关实现和有意义的验证；视觉任务需确认实际图片输入及可见结果。
- 依据调用来源和顺序判断重复执行。相同上传回执出现在多次页面读取、交接或模型请求中，不代表再次上传。
- 将实现缺陷、尚未验证和能力受限分别说明。没有图像输入，不能声称已经看过图片，也不能据此断定页面渲染错误。
- 不增加用户未要求的目标。例如加载、翻页与检查明显显示异常，不等于验证所有页面的完整保真、编辑交互和导出。

能力受限或缺少输入时，Observer 将真实原因交给 Organizer。Organizer 根据现有能力寻找可行路径；没有可行路径时向用户说明未完成项和所缺条件。能力及方法均未变化时，不能把原样重跑描述成有效补齐。

复盘失败或超时本身不能证明业务结果不合格，也不能直接触发业务重做。应保留原错误和已有结果，明确验收尚未完成。

## 实施顺序

### 1 让结束复盘先完成验收

调整 Observer 提示词和原始返回，使它先说明哪些要求已满足、哪些尚未满足、证据是什么，再给出效率建议。已有过程消息与完整请求引用继续复用。

Observer 阅读当前任务的原始时间线。需要追查归因时，读取相关 Worker 或 Organizer 的实际请求，而不是仅凭其他角色的总结推测其输入。完整请求按需读取，不全部重复展开进上下文；256k 仍是视野上限，超限时按任务需要选取历史原文。

验收需要直接检查代码或图像时，复用已有的只读文件、代码索引和图片读取工具，并遵守用户权限；当前 Observer 主要通过历史查询取证，这部分读取能力需要随验收功能接通。实际修改仍交给 Organizer 安排 Worker 执行。

### 2 接通 Observer 到 Organizer 的原始交接

让 Observer 可以明确请求 Organizer 继续当前任务，将问题、证据和对应用户要求原样传递。Organizer 据此派发具体补齐项，Worker 执行并返回实际结果。优先复用现有任务恢复、交接和调度入口。

每轮执行结束后只启动一次验收；验收内部按需查询历史可以包含多次模型请求。读取历史、查询请求正文或展示结果本身不能再次触发验收。

### 3 调整结束与继续执行的衔接

现有代码在结束复盘前已经交付执行结果，需要接通后续继续执行，并明确向用户显示当前是在验收还是补齐。一次执行结束不能被表述成用户目标已经验收通过。

保留同一任务的操作、补齐和验收过程；用户取消后停止继续派发。复盘中断、模型请求失败及补齐失败保留完整原始消息，避免下一轮丢失原因。

### 4 做回归并运行真实任务

先验证消息完整性、验收触发和具体补齐的回归场景，再用下面的 PPT 任务进行真实测试。代码遗漏场景使用独立测试夹具，避免为制造缺陷修改业务项目。

## 负责运行测试的 AI 要观察什么

观察对象是本地 Agent 的实际执行和验收。PPT 操作应由被测试 Agent 完成；负责测试的 AI 读取原始轨迹、实际请求和结果进行核查。独立查看截图得到的判断，应注明是测试者的观察，不能算成 Agent 已完成视觉验收。

| 阶段 | 核对结果 |
| --- | --- |
| 服务探测 | 确认访问到目标编辑器；现有服务可用时复用，检查启动或恢复是否有具体原因 |
| 可见浏览器 | 实际打开可见 Chrome，或复用仍可控制的原页面；失败和恢复均保留 |
| 上传加载 | 指定文件实际加载完成；统计真实上传调用，区分原始回执与再次上传 |
| 初始状态 | 实际确认第 1 页及总页数，且属于指定文档 |
| 截图翻页 | 第 1 页与第 2 页截图存在，实际翻页成功；图像输入和视觉判断与截图捕获分别核对 |
| 浏览器诊断 | 保留控制台及请求结果，说明观察覆盖范围；数量和状态来自实际记录 |

六个阶段用于核对具体任务与 Flow 展示，不能为了凑节点新增没有实际工作的确认任务。

重点核对这些现象：

- 同一上传编号多次出现，是否被误报为多次上传。
- 图片保留在后续上下文但没有新选图，是否被误报为没有图片输入或重复视觉尝试。
- 原始记录中的执行者、轮次、调用编号和失败标志是否到达接收角色。
- 是否漏掉失败恢复、超时、已完成成果或未确认事项；请求耗时按实际请求记录统计。
- 总结是否与真实操作一致，是否错误沿用旧轮次要求。
- Observer 是否只在本轮执行结束后验收；信息已经在上下文中时，是否仍无目的地重复查历史。
- 自动补齐实现后，是否只处理具体缺口，并保留已完成的加载、页面和诊断成果。

记录每次模型请求所属角色、轮次、耗时和读取历史的原因。复盘中的多次历史查询请求不等于宿主重复启动了多次验收。

## 续聊和补齐的测试场景

| 场景 | 做法与检查重点 |
| --- | --- |
| 正常完成 | 使用上面的任务；已满足要求时验收通过，不无故再派发一轮 |
| 复用旧会话 | 续聊：“在刚才的页面上再检查一下第 1 页和第 2 页，保留窗口和服务。”检查原连接复用和本轮操作归属 |
| 新要求覆盖旧要求 | 先要求复用已加载文档，后明确要求重新加载一次；检查是否遵循新要求，是否将不同轮次的上传混算成本轮重复 |
| 代码实现遗漏 | 独立夹具中的用户要求包含输入校验和明确错误返回，初次结果只实现其中一项；Observer 应依据代码或验证指出缺口，Organizer 补齐后再次验收 |
| 视觉能力受限 | 使用隔离配置或模拟响应保留图像输入不可用场景；原因完整传递，不把截图回执当成看过图片，不在能力未变时原样反复重试 |
| 同文返回与回执引用 | 不同工作返回相同文字，或同一回执出现在多次读取中；核对原工作身份和真实调用次数 |
| 请求超时或用户取消 | 检查错误原文和未完成状态是否保留；验收超时不能被当成业务缺陷，用户取消后不继续派发补齐 |

正常测试沿用当前模型与视觉配置，不根据旧测试中的 `unknown` 或 `supported` 假定本轮能力。能力受限场景单独隔离，不覆盖用户的正常配置。

## 验收依据和保存记录

自动补齐功能完成的依据：Observer 能以原始证据指出确切缺口，Organizer 能收到完整交接并安排补齐，补齐结果再次验收；满足要求后交付，受限时如实说明所缺条件。过程中不增加宿主事实摘要、自动记忆写入或无目的的重复执行。

真实测试保存任务编号、用户原始要求、按序消息、实际角色请求引用、截图文件、诊断结果、验收结论，以及发生补齐时的交接和后续操作。汇总中的每项完成、失败和重复结论都应能定位到原始记录；耗时区分模型请求等待与工具执行。

本地测试证据可放在项目现有的 `.codex-workspace-mcp/ppt-agent-observation/` 目录。项目文档记录结论和证据位置，不复制鉴权信息或完整模型配置。
