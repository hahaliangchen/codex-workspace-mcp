# Agent 视觉输入接通计划

日期：2026-10-08。

## 当前基础

本轮已完成跨系统浏览器查找与进程端口归属检测、角色原始消息和失败原因传递、最终正文展示未确认事项、Observer 增量观察与结束复盘，以及任务结束后保留工具和 Flow 历史。

示例 PPT 的实际任务已经验证六个独立阶段：服务探测、打开可见浏览器、上传并等待加载、读取初始页码、截图与翻页核对、浏览器诊断。六个任务复用同一个页面和上传结果；结束后刷新仍保留 20 条工具调用及原始结果。PPT 共 8 页，翻页后为第 2 页；无法读取截图内容的限制进入最终正文，结束复盘写入工作记忆。

截图捕获、图片材料保存、直接图片输入和独立视觉服务的分发代码已经存在。当前任务所用模型的图片能力配置为 `unknown`，视觉回退服务未启用，不能把这个状态当作模型已经支持图片，也不能据此断定接口一定不支持图片。下一步先验证真实接口，再接通已存在的链路。

## 实施顺序

### 1. 验证实际模型接口

使用当前配置的提供商与模型，发送一张内容明确的测试图片，检查最终 HTTP 请求是否包含真实图片内容，并让模型回答只能从图片获知的细节。记录实际响应、错误原文和耗时，区分支持图片、明确拒绝图片和仍未确认三种情况。

仅在接口实际验收通过后，将对应提供商/模型的图片能力标为支持。验证期间保留现有视觉不可用场景，作为错误信息传递和正常收尾的回归用例。密钥、完整本地模型配置和业务截图不写入代码库。

### 2. 接通截图到模型的输入

检查 `browser_screenshot`、`view_image`、图片材料读取与最终模型请求之间的真实链路，复用 `src/visual_artifacts.rs` 中已有的分发方式。确认模型收到图片内容，而不只是文件路径、artifact ID、截图成功回执或 DOM 文本。

保留图片所属任务、节点、版本、页面/会话、页面状态及捕获时间。根据当前任务需要复用已有图片；页面确实变化且需要新的画面证据时再截图。图片数量和尺寸按实际接口要求处理，并明确记录处理结果。

### 3. 验证视觉判断和角色传递

| 角色 | 需要获得的内容 |
| --- | --- |
| Worker | 当前任务相关的真实图片输入，或明确注明来源的视觉服务结果；实际能力失败原因 |
| Observer | 当前观察所需的图片/视觉结果和新增活动；完整保留相关原始失败信息 |
| Organizer | Worker 和 Observer 的原始判断、图片引用、可确认范围及未确认事项，据此安排后续任务和交付结果 |

检查 `visual_check_result` 是否与实际输入对应，能指出从哪张图看到什么，以及哪些内容没有确认。截图成功、文档已加载、页码正确与视觉检查通过分别记录。Organizer 的最终正文必须展示仍未确认的视觉事项。

能力未知、接口拒绝图片、请求失败等情况保留完整原因，由 Worker 和 Organizer 根据上下文决定下一步；不增加固定重试次数、强制确认回合或宿主代替模型判断业务结果的规则。

### 4. 按验证结果选择视觉路线

当前模型支持图片时，先完成直接输入链路的验收。当前模型明确不支持图片时，再选择实际可用的视觉模型或已有独立视觉服务进行配置和验收。能力尚未确认时继续如实报告，不擅自声明可用。

使用独立视觉服务时，保留服务来源、所看图片、原始结果和失败信息；各角色引用该服务的实际观察，不把转述写成自己直接看到了图片。任务模型和视觉模型的配置及能力要分别清楚展示。

### 5. 用示例 PPT 完成实际验收

重新运行示例 PPT 任务，检查六个任务阶段及前序结果复用，实际验证加载画面和翻页后的画面。让模型指出图片可见的内容、页码，以及与目标有关的空白、裁切、缺失或排版问题；不能确认的细节保留限制，不声称已经验证了未执行的编辑交互。

再回归视觉不可用场景，确认原因完整进入 Worker、Observer、Organizer 和最终正文，任务能依据已有事实交付实际结果。检查结束后刷新页面仍可查看工具输入输出、Flow 和视觉材料。

日常 Observer 继续使用增量上下文；只在任务结束复盘时查看完整工作路径。检查复盘是否准确区分真实调用、能力回执与宿主自动采集，并记录有依据、可复用的经验。

## 完成依据

- 实际模型请求包含图片内容，模型回答与测试图片和 PPT 截图相符。
- 视觉结果与对应页面、任务和图片记录一致，角色间传递不丢失判断或失败原因。
- 支持、未知和失败场景均有真实证据或明确的不确定状态，最终正文展示剩余限制。
- 任务结束后工具结果、Flow 与视觉材料仍可查看，完整复盘及记忆写入正常。
