# 启动项目流程观察

会话：`task_1a104d9ad5a18db34427d6c2d4c`，第 15 轮，用户请求“给我启动一下，然后打开示例ppt 我看下”。

观察时间窗口：2026-10-05 16:09:46 至 16:27:51。后端状态仍为 running，27 个执行步骤、31 次工具调用（17 次 run_command、7 次 read_file、3 次 list_dir 等），18 次组织者启动，37 条观察者过程审查。该数字是观察快照，不是任务最终总数。

## 已确认的问题

1. **continue 输入丢失。** 第 5 步组织者提供 material_ids=[3,160,161]，调度状态仍为 []。第 16 步要求 final_answer=true，下一份工作包仍为 false。第 18 步提供禁止重复请求旧 IPv4 地址的约束，请求 313 中缺失。第 19 步明确要求改用空闲端口，请求 317 未包含这条组织者决策。代码仅执行 continue_current()，没有应用 orders 或传递 reason。Worker 始终拿到原工作包。
2. **端口归属判断错误。** 第 8 步 Start-Process 后只检查 3000/3001 是否连通，将宿主服务也当成项目状态。第 15 步结果明确显示 127.0.0.1:3000 和 3001 属于 PID 25604 的 codex-workspace-mcp，Rspack 使用另一监听地址。反复访问这些 URL 得到 404，不能证明 PPT 前端页面启动失败，更不能证明启动成功。
3. **后台启动丢失日志和管理关系。** Start-Process 没有捕获 npm/Rust/WASM/Rspack 日志，父 shell 的退出码不是服务器就绪结果；返回的外层 PID 不代表所有组件正常。新四个项目进程工具尚未加载到观察时的服务，请求中的工具仍只有 run_command 可执行项目。
4. **组织者调用过密。** 每个纯汇报轮触发交接；达到 12 轮无修改/新检查阈值后，计数一直超阈值，后续每轮都再次请求组织者。更新后的继续执行决策又未抵达 Worker，形成额外模型往返。
5. **浏览器能力与任务目标不匹配。** Worker 未获得浏览器交互工具，仍查询 Playwright/Puppeteer 和调试端口，并把 Chrome 标题当成打开动作的结果。打开 URL 不能证明在应用内打开了示例。组织者也缺少实际工具清单，没提前区分可完成的启动和无法完成的界面交互。
6. **结论混淆。** 状态里存在“app-running”但实际页面未就绪；第 19 步还形成“不是地址绑定问题”的结论，与已知端口归属冲突。部分 shell 输出的中文已经乱码，增加判断困难。不能只把所有历史结果原样叠入当前判断。

Observer 已多次识别端口冲突、重复查询以及需要换端口，第 25、26 步组织者也复述了建议；问题不是完全没看见，而是调度输入没同步，以及 Worker 对实际操作和完成条件的判断仍不合格。

## 本次代码修正

- 所有工作包自动画 Flow，简单问答一个节点，不增加规划请求；复杂工作仍可递归分解。
- continue 更新约束、材料和结论选择，并向 Worker 提供最新 organizer_handoff；契约字段变化明确报错，不静默忽略。
- 同一停滞阈值不会在每轮重复触发组织者，总计数仍保留；纯汇报检测不取消。
- 组织者收到实际工具清单。提示词明确区分打开 URL、界面交互和实际文档加载。
- 上一轮新增的项目进程工具提供日志、进程组管理、启动前端口检查和就绪结果，需编译重启后加载。

## 推荐工作路径

确定项目脚本、目标端口及示例入口 → 用后台项目脚本启动并核对页面就绪 → 通过真正的浏览器交互加载示例。缺少浏览器工具时，交付可访问地址并明确剩余加载步骤。服务就绪和示例打开应分别验收，不能用一个“output”笼统包住所有步骤。

本次仅观察该任务并修改 Agent 代码，没有代替它启动另一个 PPT 服务，没有停止其当前任务，也没有声明示例已打开。
