# 任务协作与历史排序

一个主 Agent 负责理解需求、制定计划、分配工作、验证产物和最终回复。
每个会话最多同时运行 5 个任务子 Agent；压缩子 Agent 不占名额。
后台视觉分析仍是只读工具任务，不参与任务子 Agent 的计数。

## 派发和验收

`spawn_agent(name, task, context, asset_ids)` 立即返回 `agent_id`；`context` 和
`asset_ids` 可省略。宿主继承主 Agent 派发时的执行上下文：原始需求、确认记录、
压缩摘要、已读材料、工具回执、资产引用和技能激活状态。主 Agent 只追加简短的任务、
独占范围、验收标准和需要优先读取的 `asset_ids`，已明确的要求和验收规则不重复输出。

父窗口较小时整窗继承，正文与引用保持原有状态，无额外模型调用。估算输入超过委派阈值
（压缩阈值的 1/2，最低 16k tokens）时，宿主使用 `compaction_view` 生成投影：保留原始
用户要求、当前计划和回执叙述、事件序号与资产句柄；工具结果/参数正文和内联图片换成
引用，当前激活技能的最新指令仍从资产库恢复。子 Agent 用 `read_asset` 读取所需正文，
用 `read_session_history` 按 `event_seq` 补充历史。投影后仍超过输入预算 3/4 时拒绝派发，
要求主 Agent 先压缩或拆分任务。父窗口的工具调用转换为有来源的历史数据，去除原生调用
ID 和推理，避免成为子任务待执行的工具协议；资产来源与引用保持不变。各窗口独立压缩、
释放资产，互不修改。

子 Agent 继承当前提供商/模型、权限、插件作用域和已认证项目绑定，不可递归派发。
已激活技能仍受当前注册作用域和权限检查；失效后才需要重新加载。
Git 仓库的可写子任务默认从干净的当前 HEAD 创建独立 `codex/delegate-*` 分支和 worktree；
本地文件工具在该 worktree 中执行，主工作树不会直接收到子任务改动。派发前若主工作树有
未提交改动，宿主拒绝建立 Git 子任务，避免子任务在缺少这些改动的基线上工作。子任务
结束时宿主把其 worktree 中未忽略的改动提交到专属分支，保留分支和 worktree 供复查。
主 Agent 用 `inspect_agent_changes` 看基线到分支提交的 Diff，再以该提交调用
`merge_agent_result`；合并冲突留在主工作树中供明确解决，成功合并后才可验收为 accepted。
同一远端页面只分给一个写入者；PPT 仍通过后端权限、任务、文件版本和预期 revision 执行。
宿主对明确路径的本地写入和 PPT `write_file` 记录跨进程资源占用；运行中的另一写入者会被
拒绝，子任务终态释放占用。Git 隔离覆盖宿主路由的本地工具；允许执行任意程序的
FullAccess 仍须遵守其工作区边界，宿主不能从任意命令预测其全部写入路径。

`wait_agents(wait_ms)` 只在独立工作已耗尽时等待，最长 30 秒。
完成回执按持久化的完成事件顺序自动交给主 Agent，只含状态与报告资产引用，正文不会自动进入主窗口。主 Agent 按需用 `read_asset` 查看报告及其中的资产索引，再按引用检查具体产物。索引包含输入和输出回执，本身不是成功证明。报告不是人类的新指令。
完成状态仅表示子 Agent 返回；主 Agent 检查实际文件、版本和测试证据后，调用
`review_agent_result(agent_id, decision, evidence, evidence_refs, git_head)`。decision 为 accepted、
needs_work 或 unresolved。需要返工时重新派发明确修正任务；未解决项须明确交代。
accepted 必须引用主 Agent 在子任务完成后取得的成功工具回执 `event_seq`。Git 子任务还要
引用 Diff 查看、合并和集成后变更文件读取的回执，提交必须仍在分支 HEAD 且已进入主分支；普通本地文件读取要
与当前内容哈希一致。宿主能核对回执和版本，业务正确性及测试是否充分仍由主 Agent 判断。
所有子任务报告收齐并记录验收后，主 Agent 才能交付最终回复。视觉检查仍单独收齐。

子 Agent 的产物、工具结果和生成参数沿用通用资产协议，交接报告带持久化引用索引；压缩后仍能找到此前的资产。输出结果与索引归档成功后，在同一事务中删除该子 Agent 的工作窗口及明确归属于它的压缩窗口/冻结快照。取消、失败和重启中断同样回收。原始事件、模型请求记录、不可变资产和项目文件继续保留；不删除审计历史，也不把子 Agent 的工作上下文合并进主窗口。没有归属信息的旧压缩快照保留。

`cancel_agent(agent_id)` 只取消本会话的指定任务；取消不撤销已经执行的操作。
取消主会话会传播给其任务子 Agent。执行器用持久化实例身份与 30 秒租约，每 5 秒续租；
另一宿主的有效租约不会被本进程回收。租约过期或本进程执行器消失的任务标为 interrupted，
保留原始过程与产物；不自动重放，也不自动判定通过。

## 三种顺序

| 层 | 顺序 | 用途 |
| --- | --- | --- |
| 原始日志 | 本会话全局 seq 的实际发生顺序 | 审计、重放、请求上下文与证据引用 |
| 聊天展示 | 子任务卡片固定在派发位置；卡片内按自身事件顺序 | 避免并发输出交错、避免完成后卡片跳动 |
| 主 Agent 工作窗口 | 原生主 Agent 工具交换保持顺序，报告按实际完成顺序交付 | 及时消费结果，不把其他 Agent 的工具协议冒充主 Agent 的调用 |

例如先派发 A、后派发 B，而 B 先结束：聊天仍显示 A 卡片、B 卡片；B 卡片先更新
为“待验收”。主 Agent 先收到 B 的报告，先验证 B；A 的报告到达后再处理 A。
不会为了显示 A 在前而阻塞 B 的交付，也不会移动 B 的原始完成记录。

`subagent/start` 是卡片锚点；`subagent/event` 保存 agent_id、agent_seq、
event_type 和原始事件；`subagent/end` 保存返回结果；`subagent/review` 保存
主 Agent 的验收。全局 seq 和 agent_seq 在持久化事务内分配。
agent_id 隔离不同子 Agent 的工具调用 ID，即使提供商产生同名 call ID 也不串结果。
主会话模型默认只接收派发回执、任务状态和完成报告引用，子 Agent 完整过程按需读历史。
有未验收子任务或视觉检查时，主 Agent 的模型正文先缓冲到本轮响应结束，以免尚未验证的
最终答复作为逐字增量显示；子任务卡片和工具事件仍按实际发生顺序更新。

宿主界面和 PPT 页面都使用稳定卡片；PPT 页面保持简化展示，只展示子任务叙述、
进度、结果及验收，不展示工具参数、SVG 正文或思考文本。

## 验证

- 延迟子任务与快速子任务并发，主 Agent 可继续写独立文件。
- 完成顺序逆于派发顺序；原始事件、聊天卡片、主窗口报告分别保持各自顺序。
- 提前最终回复不交付；主 Agent 核对产物并验收后才能结束。
- 第六个并发任务拒绝；压缩窗口不占任务名额；子 Agent 不能递归派发。
- 父会话取消、跨会话访问拒绝、重启中断不重放。
- 完成回执不含报告正文；显式读引用后才加载报告，并由主 Agent 读实际产物验收。
- 大窗口派发只投影需求/计划/回执叙述与引用；资产正文未进入子窗口，可按 asset_id 读回。
- 激活技能的最新指令在投影后仍可用；投影超预算时明确拒绝，不静默丢历史。
- 终态归档与窗口回收原子提交，清理仅限本子 Agent；历史、资产与其他窗口保留。
- 原生工具交换不串入主窗口；相同工具 call ID 不跨子 Agent 串结果。
