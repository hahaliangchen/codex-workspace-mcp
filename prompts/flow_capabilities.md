Flow runtime capabilities (version 14; JS subset, not Node.js):
- Top-level statements run in order. Top-level return is invalid; put data the program needs in its code or read it with the imported tools. Define ordinary top-level functions and call them with positional parameters; missing arguments are undefined and extra ones are ignored, but @virtual functions take exactly their parameters.
- Values use an internal VM heap; objects and arrays preserve identity across ordinary calls. Supported syntax includes const/let/var, arrays and objects, destructuring and defaults in declarations, ordinary function parameters and catch, literal spread, spread in calls and rest parameters, optional function calls, local assignment and updates, object/index assignment and updates, arithmetic and comparisons, if/else, ternary, for/for-of/for-in with simple bindings, switch, labeled break/continue, try/catch/finally/throw, template strings and assert. let/const are block-scoped: an inner block may redeclare and shadow a name, and reading one before its declaration throws ReferenceError. var is function-scoped and hoisted. Non-simple parameters initialize in a separate parameter scope, so defaults and their closures cannot see body bindings. A function sees its own variables and top-level ones, not its caller's locals; pass those as arguments. Empty strings, false, null and zero are false; objects and arrays are true. `&&` and `||` return operands. Tool and AI inputs/outputs cross a JSON boundary; cyclic and non-JSON values are rejected there.
- Common strings/arrays support includes, indexOf, slice, at, concat; strings support lastIndexOf, startsWith, endsWith, trim, case conversion, split, replace, replaceAll, match; arrays support push and join. Functions are values: nested function declarations, function expressions, arrows and object method shorthand create closures over their enclosing scope that can be stored, passed and called; built-ins such as String and imported tools can be used as values too. Array callback methods accept synchronous function values, multi-statement and nested callbacks; callbacks can call tools and resume after persistence. String replace/replaceAll also accept replacement functions. Array map also accepts async callbacks. JSON.parse/stringify, Array.isArray, Object.keys/values and typeof are available. Regex literals support test and match, not full JavaScript RegExp.
- `path.join/resolve/relative/normalize/dirname/basename/extname` and `url.parse` are deterministic Rust-backed computations, not Node imports or filesystem access.
- `import * as io from "host:io"` and `import {read as load} from "host:io"` bind authorized tools. Tool methods accept one JSON object and return their actual tool result. Use `read_tool_contracts` for real names, parameters and return contracts.
- An empty function with an adjacent `@virtual` comment declares an AI capability and its return contract; it may also be nested inside another function. Ordinary functions use their implemented body. A virtual function in the main program is implemented by AI-written code; one declared inside that implementation runs as a tool loop with the tools the implementation imports.
- Async @virtual functions run in independent windows; they receive only their arguments, as values at invocation. Promise.all collects results in input order. Model requests share the configured concurrency limit.
- async functions return Promises; await suspends and resumes. Promise.resolve/reject, new Promise, then/catch/finally and Promise.all/allSettled/race/any are available. Import async tools from host:<library>/promises; independent file reads may be batched. Errors propagate through await. Promise ordering follows JavaScript microtask order, including the extra turns when a Promise resolves to another Promise. Using a call of a top-level async function or a /promises tool directly as a value (reading a property, an operator, a condition, assert or a template) without await is a compile error; save the Promise or await it. Ordinary thenable assimilation and extracted Promise methods remain unsupported. Unsupported syntax includes function*/yield and call()/ai() wrappers. The runtime is a JS subset, not Node.js.
- Tool and AI calls can fail; exceptions can be handled. Uncaught runtime failures stop the current flow. Do not repeat effects with unknown outcomes or claim acceptance based only on successful execution.
