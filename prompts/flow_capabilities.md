Flow runtime capabilities (version 12; JS subset, not Node.js):
- Top-level statements run in order, with `input` as the supplied JSON value. Top-level return is invalid. Define ordinary top-level functions and call them with positional parameters.
- Data is JSON. Supported syntax includes const/let/var, arrays and objects, destructuring, assignment and updates, arithmetic and comparisons, if/else, ternary, for/for-of/while/do-while, break/continue, try/catch/throw, template strings and assert. False, null and zero are false; other values are true. `&&` and `||` return booleans. JSON values are snapshots.
- Common strings/arrays support includes, indexOf, slice, at, concat; strings support lastIndexOf, startsWith, endsWith, trim, case conversion, split, replace, replaceAll, match; arrays support push and join. JSON.parse/stringify, Array.isArray, Object.keys/values and typeof are available. Regex literals support test and match, not full JavaScript RegExp.
- `path.join/resolve/relative/normalize/dirname/basename/extname` and `url.parse` are deterministic Rust-backed computations, not Node imports or filesystem access.
- `import * as io from "host:io"` and `import {read as load} from "host:io"` bind authorized tools. Tool methods accept one JSON object and return their actual tool result. Use `read_tool_contracts` for real names, parameters and return contracts.
- An empty function with an adjacent `@virtual` comment declares an AI capability and its return contract. Ordinary functions use their implemented body. `define_task_body` can implement the current virtual function with the same signature and returns to its caller.
- Authorized `fork(helper, arg1, arg2)` and `join(...)` invoke concurrent agents and collect results; fork receives a snapshot, not later parent changes. Git worktrees require explicit inspection and merge before parent reads. A child cannot fork.
- `await` on a value, ordinary function, AI capability or tool call waits for its result; `async` functions are allowed. Flow effects already suspend and resume, so this is sequential host execution, not JavaScript Promise scheduling. `await Promise.all` supports only advertised read-only operations, at most 32; Directly awaited chains rooted in Promise.resolve/reject with simple initial values (no effects or property access) support then/catch with zero or one simple arrow parameter and an expression body; these are sequential continuations, not Promise objects. Other Promise objects and general Promise chains are unavailable. Unsupported features include classes, nested/anonymous functions, general arrow functions, general modules, exports, TypeScript types, function*/yield and call()/ai() wrappers. Compiler diagnostics identify unsupported code before effects; use them to revise or explicitly report a limitation.
- Tool and AI calls can fail; exceptions can be handled. Uncaught runtime failures stop the current flow. Do not repeat effects with unknown outcomes or claim acceptance based only on successful execution.
