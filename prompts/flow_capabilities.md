Flow runtime capabilities (version 14; JS subset, not Node.js):
- Top-level statements run in order, with `input` as the supplied JSON value. Top-level return is invalid. Define ordinary top-level functions and call them with positional parameters; missing arguments are undefined and extra ones are ignored, but @virtual functions and fork targets take exactly their parameters.
- Values use an internal VM heap; objects and arrays preserve identity across ordinary calls. Supported syntax includes const/let/var, arrays and objects, destructuring, local assignment and updates, object/index assignment and updates, arithmetic and comparisons, if/else, ternary, for/for-of/while/do-while, break/continue, try/catch/throw, template strings and assert. let/const are block-scoped: an inner block may redeclare and shadow a name, and reading one before its declaration throws ReferenceError. var is function-scoped and hoisted. A function sees its own variables and top-level ones, not its caller's locals; pass those as arguments. Empty strings, false, null and zero are false; objects and arrays are true. `&&` and `||` return operands. Tool and AI inputs/outputs cross a JSON boundary; cyclic and non-JSON values are rejected there.
- Common strings/arrays support includes, indexOf, slice, at, concat; strings support lastIndexOf, startsWith, endsWith, trim, case conversion, split, replace, replaceAll, match; arrays support push and join. Functions are values: nested function declarations, function expressions, arrows and object method shorthand create closures over their enclosing scope that can be stored, passed and called; built-ins such as String and imported tools can be used as values too. Callbacks of array map/filter and similar methods must still be written directly in the call, as an expression arrow or an anonymous function with a single return, with up to value/index/array parameters; they may nest callbacks and closures and use visible variables and tools. Callbacks with statement blocks, async callbacks and passing a function variable as the callback are not yet available. JSON.parse/stringify, Array.isArray, Object.keys/values and typeof are available. Regex literals support test and match, not full JavaScript RegExp.
- `path.join/resolve/relative/normalize/dirname/basename/extname` and `url.parse` are deterministic Rust-backed computations, not Node imports or filesystem access.
- `import * as io from "host:io"` and `import {read as load} from "host:io"` bind authorized tools. Tool methods accept one JSON object and return their actual tool result. Use `read_tool_contracts` for real names, parameters and return contracts.
- An empty function with an adjacent `@virtual` comment declares an AI capability and its return contract. Ordinary functions use their implemented body. `define_task_body` can implement the current virtual function with the same signature and returns to its caller.
- Authorized `fork(helper, arg1, arg2)` and `join(...)` invoke concurrent agents and collect results; fork receives a snapshot, not later parent changes. Git worktrees require explicit inspection and merge before parent reads. A child cannot fork.
- `await` on a value, ordinary function, AI capability or tool call waits for its result; `async` functions are allowed. Flow effects already suspend and resume, so this is sequential host execution, not JavaScript Promise scheduling. `await Promise.all` supports only advertised read-only operations, at most 32; Directly awaited chains rooted in Promise.resolve/reject with simple initial values (no effects or property access) support then/catch with zero or one simple arrow parameter and an expression body; these are sequential continuations, not Promise objects. Other Promise objects and general Promise chains are unavailable. Unsupported features include classes and `this`, general modules, exports, TypeScript types, function*/yield and call()/ai() wrappers. Compiler diagnostics identify unsupported code before effects; use them to revise or explicitly report a limitation.
- Tool and AI calls can fail; exceptions can be handled. Uncaught runtime failures stop the current flow. Do not repeat effects with unknown outcomes or claim acceptance based only on successful execution.
