# 用这套思维解决问题

这是一套从过往技术讨论中提炼的推理方法，不是性格描述或沟通规范。当前问题的事实优先于历史经验；旧项目的具体方案不能直接搬到新问题。

## 核心推理循环

1. **从具体实例入手。** 找到真实输入、真实输出和期望结果。直接看样本、运行画面、中间数据、代码或日志；先确定现象，再解释原因。
2. **抽象对象与关系。** 问清楚问题里的基本单元是什么，它们如何归属、依赖或相互影响。把必须保持的语义关系写成可检查的约束，再决定数据结构或算法。
3. **还原实际运作链路。** 从入口到最终结果逐段追踪：每一步接收什么、产生什么、由谁负责判断。寻找信息丢失、重复计算、错误归属、状态未传递或配置未进入实际路径的位置。
4. **提出能被推翻的机制假设。** 对关键疑点给出少数解释，并指出什么观察能区分它们。用小实验控制变量，查看中间产物；不要只凭最终现象猜原因。
5. **做可验证的实现。** 先验证核心机制能否解决问题，再扩展到变化的输入。让规则由关系和约束推导出来，避免为当前样本写死常量；复杂分支只有在真实反例要求时才加入。
6. **用结果修正模型。** 在真实使用路径上复测，检查最终用途是否得到改善。若结果不符，回到链路和假设；若出现新反例，修改抽象，而不是继续维护已被事实否定的解释。

## 常用的思维动作

- **找本质关系。** 先判断内容属于谁、什么条件共同决定结果，再看表面位置、词频或局部相似度。必要时比较“正确与错误”“存在与移除”“改动前与改动后”，识别真正起作用的条件。
- **从粗到细缩小范围。** 先定位可靠的对象、区域或阶段，再做细判定；当早期判断不可靠时，保留回退，避免过早过滤掉正确结果。
- **把类比变成可计算方案。** 可以大胆用空间、矩阵、因果或其他结构重新理解问题，但要进一步定义对象、判定条件、可观察量和验证实验。
- **区分共同流程与特殊路径。** 比较不同样本真正共享的机制，尽量用同一规则处理；无法可靠覆盖的类型，明确其触发条件和回退方式。
- **保留基线，衡量整体收益。** 新旧算法或配置要能比较。除了准确度，还看最终任务效果、端到端时间、各阶段耗时、内存和状态传递；以当前问题决定何时停止优化。

不要把单次实验的阈值、项目特定方案或未经核实的其他 AI 观点升格为通用原则。
