# PPT HTML 设计

让模型专注内容与视觉设计。只持久化 PPTX；JSON 是转换时的内存中间表示，记录对象身份、组关系、模板标注和 PPT 来源，HTML/CSS 是设计工作视图。每次从编辑器最新快照转换，不要求另存设计 JSON。产物是静态 HTML 与独立素材引用。AI 的所有页面内容修改都通过 HTML，包括只改一个字；不直接输出 JSON 编辑命令或操作 OOXML。用户手动操作编辑器后，宿主自动刷新 HTML，旧版本失效。

## 设计前必读

**每次设计或重设计，必须完整读取 [Anthropic 原版审美设计](references/anthropic-design-verbatim.md)，逐项用于构思与自检，不能仅凭本入口的概述代替。** 这是历史 html2pptx skill 的 Design Principles 至 Layout Tips 原文，包含完整配色示例和视觉处理选项，未翻译、删节或改写。它是本 skill 的核心设计指导。

同时读取 [HTML 格式与项目约束](references/html-format.md)。原版设计里的构图、图表、字体与背景效果是视觉选择：按宿主支持能力表达，复杂部分制作成独立素材；不要因基础转换器能力有限而把所有页面降成同一种卡片排版。字体使用宿主实际可用且覆盖正文语言的字体；原文的英文 web-safe 字体清单不能替代中文字体检查。尺寸使用本项目的 1280×720。

## 工作方式

先结合内容、读者、品牌和模板参考说明设计方向，随后直接设计。页数服从用户要求和内容量，不默认 5 页。模板里的布局和示例图可参考或复用；原有 Logo、品牌文字、固定背景和未标注的原有图片默认保留；只有制作人明确标为可变或参考素材才允许修改。不能自行删除锁定属性来解锁。空模板可以自由构图，不退回占位符填槽。

初始化、复制页面、读取模板只是中间步骤。用户已授权制作整份文稿时，持续完成所有目标页的内容、保存、检查和导出，不以“尚未完成”作为无阻碍时的结束理由。长文稿分批推进并记录进度；上下文不足时使用宿主压缩/历史能力继续，不重新初始化。确有无法自行修复的错误或必需输入缺失时，说明具体阻碍和已保存范围。

- **修改现有页**：从宿主提供的绝对定位 HTML 投影开始，保留已有 ID、节点种类及组关系，修改请求涉及的内容与外观。
- **制作模板**：读取 [模板用途与保护](references/template-authoring.md)。同样通过 HTML 修改；只有模板制作模式允许向宿主提交用途变更，涉及解除固定必须由制作人明确确认。
- **重新设计页面**：围绕内容、风格与素材设计，可以使用 flex/grid。复用节点保留 ID；新增节点不伪造已有 ID，由程序分配身份。现有组关系需要变化时通过宿主支持的关系编辑操作处理，不能靠改 HTML 属性绕过 JSON 约束。
- 复杂插画、图标、照片和示意图通过可用素材、图标库或生成工具取得，作为独立资产加入。不能用单个汉字、缺字方框或生僻字符冒充图标。模板里的总结示意图若标为参考，应结合当前内容重新组织，不能直接照搬示例内容。
- 有真实数据才设计相应数据图；缺少数据时用定性关系图或明确的内容说明。

## 输出与检查

每页输出一份完整静态 HTML；保留宿主提供的页面 ID、版本和资源身份。宿主保存本次原始 HTML，比较修改前后的测量结果，按 ID 和属性仅合并实际变化；未变节点保持原 JSON 值。CSS 布局引起的相邻节点联动也会被识别。锁定、绑定及分组以 JSON 为准。宿主负责浏览器测量、诊断、差异合并与 PPTX 导出；本 skill 不调用 Anthropic 的 html2pptx.js、PptxGenJS 或自行写 OOXML。

完成后完整读取 [原版视觉检查](references/anthropic-visual-qa-verbatim.md)，应用其中的视觉检查标准。该原文提到的导出与缩略图命令仅记录上游流程；这里使用宿主提供的 HTML、编辑器和导出预览，不执行不存在的脚本。所有页面都要检查，长文稿分批记录已检查范围。

既检查裁切、遮挡、对齐和对比度，也检查内容完整、占位符残留、图标缺失、图与主题是否相关、构图是否失衡。布局检测通过不代表审美检查完成。修复设计稿后重新测量与观察，不让转换程序自动缩字、自动套布局或隐藏溢出来掩盖问题。未得到实际渲染或导出验证时，说明验证范围，不能报告整份已检查。
